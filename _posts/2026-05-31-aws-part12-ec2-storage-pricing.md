EC2 인스턴스는 연산만 담당하고, 데이터를 실제로 저장하는 것은 **EBS**가 맡습니다.  
그리고 비용과 보안이라는 두 가지 운영 핵심을 함께 정리합니다.

---

## EBS (Elastic Block Store)

> **정의:** EC2에 연결하여 사용하는 **가상의 하드드라이브**

> **비유:** EC2가 컴퓨터 본체라면, EBS는 그 본체에 꽂는 **외장 하드**입니다.  
> 본체(EC2)를 바꿔도 외장 하드(EBS)의 데이터는 그대로 남아 있습니다.

### EBS의 핵심 특성

| 특성 | 내용 |
|---|---|
| **연결 방식** | 네트워크를 통해 EC2와 연결 (물리적 케이블 아님) |
| **가용영역** | EC2와 **동일한 AZ**에 존재해야 함 |
| **가용성** | 99.999% 목표, 데이터 자동 분산 저장 |
| **루트 볼륨 기본 동작** | EC2 종료 시 함께 삭제 (설정 변경 가능) |
| **추가 볼륨** | EC2 실행 중에도 자유롭게 추가/분리 가능 |

```
[루트 볼륨 기본 설정]
EC2 종료 → EBS 루트 볼륨도 함께 삭제 ❗

[설정 변경 후]
EC2 종료 → EBS 루트 볼륨은 유지, 나중에 다른 EC2에 붙일 수 있음 ✅
```

### EBS 볼륨 타입 5가지

| 유형 | 타입명 | 주요 용도 | 최대 IOPS |
|---|---|---|---|
| **범용 SSD** | GP (gp2, gp3) | 일반 목적, 부팅 볼륨, 중소형 DB | 16,000 |
| **프로비전된 IOPS SSD** | io (io1, io2) | IOPS가 매우 중요한 고성능 DB | 64,000 |
| **쓰루풋 최적화 HDD** | st1 | 대용량 순차 읽기/쓰기 (하둡, 로그) | 500 |
| **콜드 HDD** | sc1 | 접근 빈도가 낮은 저비용 파일 저장 | 250 |
| **마그네틱** | Standard | 백업, 드물게 접근하는 데이터 보관 | 40~200 |

> **💡 선택 기준:** 빠른 응답(IOPS)이 중요하면 SSD 계열, 대용량 처리(쓰루풋)가 중요하면 HDD 계열

## 스냅샷 (Snapshot)

> **정의:** 특정 시점의 EBS 상태를 백업한 데이터

> **비유:** 게임의 **세이브 포인트**입니다.

**증분식 백업:**

```
첫 번째 스냅샷 (전체 데이터 100GB 저장)
       ↓
두 번째 스냅샷 (바뀐 5GB만 저장) ← 비용 절약 핵심
       ↓
세 번째 스냅샷 (바뀐 2GB만 저장)
```

| 특성 | 내용 |
|---|---|
| **저장 위치** | S3 (99.999999999% 내구성) |
| **백업 방식** | 증분식 (변경분만 저장) |
| **활용** | 다른 AZ나 리전으로 복사해 재해 복구 가능 |
| **아카이브 옵션** | 최소 90일 보관, 복원 최대 72시간 소요 (저비용) |

## AMI (Amazon Machine Image)

> **정의:** EC2를 실행하는 데 필요한 **모든 것을 담은 템플릿**

> **비유:** 컴퓨터를 통째로 복제/복구할 수 있는 **이미지 파일(ISO)** 입니다.  
> OS, 설치된 소프트웨어, 설정 파일까지 한번에 담겨 있습니다.

```
AMI
├── 스냅샷 (1개 이상) ← 실제 디스크 데이터
├── 사용 권한 ← 누가 이 AMI를 쓸 수 있는지
└── 블록 디바이스 매핑 ← EBS 용량 및 개수 정보
```

| 구분 | 스냅샷 | AMI |
|---|---|---|
| **내용** | EBS 볼륨 데이터 | OS + 앱 + 설정 포함 전체 서버 상태 |
| **목적** | 데이터 백업 | 서버 복제 및 배포 |
| **활용** | 특정 볼륨 복원 | 새 EC2 인스턴스를 동일한 상태로 시작 |

## 백업 자동화 도구

### Amazon DLM (Data Lifecycle Manager)

- EBS 스냅샷과 AMI의 **생성·보관·삭제를 자동화**
- **무료** 제공, 태그(Tag) 기준으로 정책 설정

### AWS Backup

- EC2뿐 아니라 **RDS, DynamoDB, EFS, S3** 등 다양한 서비스 지원
- 복원 시 VPC 설정, IAM 역할, 보안 그룹까지 해당 시점 상태로 한 번에 복원 가능

| 기능 | DLM | AWS Backup |
|---|---|---|
| 지원 서비스 | EBS, AMI | EC2, RDS, DynamoDB, EFS, S3 등 |
| 비용 | 무료 | 저장/복원 용량에 따라 과금 |
| 권장 시나리오 | EC2/EBS 전용 단순 백업 | 멀티 서비스 통합 백업 관리 |

## EC2 요금 모델

> **AWS의 가격 철학:** "미리 내지 않고, 사용한 만큼 내고, 예약할수록 더 적게 낸다."

### ① 온디맨드 (On-Demand)

> **비유:** 편의점처럼 정가에 원할 때 사고, 쓴 만큼만 냅니다.

- 약정 없음, 초/시간 단위로 과금
- 수요 예측이 어렵거나 **단기/비정기 워크로드**에 최적

---

### ② 예약 인스턴스 (Reserved Instances)

> **비유:** 헬스장 연간 회원권. 온디맨드 대비 **최대 72% 할인**

- 특정 리전 + 인스턴스 유형을 1년 또는 3년 약정
- 약정 기간 동안 사용 여부와 관계없이 비용 발생

---

### ③ Savings Plan

> **비유:** 특정 헬스장 연간권이 아닌 **전국 헬스장 이용 가능한 프리미엄 연간권**

- 인스턴스 단위가 아닌 **컴퓨팅 파워 사용량 자체를 약정**
- 예약 인스턴스보다 **유연성이 높음** (인스턴스 패밀리, 리전, OS 변경 자유)

---

### ④ 스팟 인스턴스 (Spot Instance)

> **비유:** 항공사의 빈 좌석을 파격 할인에 판매하는 것처럼, AWS의 **남는 컴퓨팅 자원**을 사용

- 온디맨드 대비 **최대 90% 저렴**
- AWS 상황에 따라 인스턴스가 **언제든 중단**될 수 있음 (2분 전 통보)

```
✅ 적합: 머신러닝 학습, 배치 데이터 처리, CI/CD 빌드
❌ 부적합: 실시간 웹서버, 데이터베이스
```

---

### ⑤ 전용 인스턴스 / 전용 호스트 (Dedicated)

- **물리적으로 완전히 격리된 하드웨어** 서버를 단독으로 임대
- 금융·의료 등 법적으로 단독 서버가 요구되거나, 특정 소프트웨어 라이선스 조건이 있을 때 사용

---

## 요금 모델 비교

| 모델 | 약정 | 할인율 | 적합한 상황 |
|---|---|---|---|
| 온디맨드 | 없음 | 없음 | 단기, 예측 불가 워크로드 |
| 예약 인스턴스 | 1~3년 | 최대 72% | 장기 고정 워크로드 |
| Savings Plan | 1~3년 | 최대 72% | 장기이나 인스턴스 유연성 필요 |
| 스팟 | 없음 | 최대 90% | 중단 허용되는 배치/학습 |
| 전용 | 필요시 약정 | 없음 | 규정/라이선스 요구사항 |

## 보안 그룹 (Security Group)

> **정의:** EC2 인스턴스를 보호하는 **가상의 방화벽**

> **비유:** 아파트 경비실처럼, 누가 들어오고 나갈 수 있는지를 통제합니다.

**기본 정책: 모두 막고, 필요한 것만 허용**

```
기본 상태: 모든 인바운드 트래픽 차단 ❌

허용 규칙 추가:
- 80/443 포트 (웹 트래픽): 전체 허용 ✅
- 22 포트 (SSH): 내 IP만 허용 ✅
- 3306 포트 (MySQL): 특정 서버 IP만 허용 ✅
```

**중요 특징:**

| 특징 | 내용 |
|---|---|
| **허용(Allow)만 가능** | 거부(Deny) 규칙을 직접 만들 수 없음 |
| **Stateful** | 인바운드 허용 시 해당 연결의 아웃바운드는 자동 허용 |
| **다중 적용** | 하나의 인스턴스에 여러 보안 그룹 동시 적용 가능 (합집합 적용) |

**주요 포트 참고:**

| 서비스 | 포트 |
|---|---|
| HTTP | 80 |
| HTTPS | 443 |
| SSH | 22 |
| RDP (Windows) | 3389 |
| MySQL / Aurora | 3306 |
| PostgreSQL | 5432 |
