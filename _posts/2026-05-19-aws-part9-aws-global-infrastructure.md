## AWS 글로벌 인프라 개요

AWS는 전 세계에 데이터센터를 분산 배치하여, 어디서든 빠르고 안정적인 서비스를 제공합니다.  
이 구조는 크게 3계층으로 이루어져 있습니다.

```
리전 (Region)
└── 가용 영역 (Availability Zone, AZ)
    └── 데이터센터 (실제 건물)

+ 엣지 로케이션 (Edge Location) ← 전 세계 CDN 거점
```

---

## 리전 (Region)

> **정의:** AWS 서비스가 제공되는 서버의 물리적인 위치 단위 (대륙/국가 수준)

> **비유:** 전국에 있는 대형 물류센터 거점입니다.  
> 서울 물류센터, 부산 물류센터처럼 각 지역마다 독립적인 거점이 있고,  
> AWS도 서울(ap-northeast-2), 도쿄(ap-northeast-1), 미국 버지니아(us-east-1) 등으로 구분됩니다.

### 리전의 특징

- 전 세계 30개 이상의 리전이 운영 중 (계속 늘어나는 중)
- 각 리전에는 **고유 코드**가 부여됨 (예: 서울 = `ap-northeast-2`)
- 리전마다 제공되는 AWS 서비스가 **조금씩 다를 수 있음**
- 리전끼리는 기본적으로 **독립적** (A 리전 장애가 B 리전에 영향 없음)

### 리전 선택 시 고려사항

| 고려 요소 | 설명 |
|---|---|
| **지연 속도 (Latency)** | 사용자가 많은 지역과 가까운 리전 선택 → 응답 속도 향상 |
| **법률·규제** | 특정 국가는 데이터를 자국 내에만 보관해야 하는 법이 있음 |
| **서비스 가용성** | 원하는 AWS 서비스가 해당 리전에서 제공되는지 확인 |
| **비용** | 리전마다 요금이 다름 (미국 버지니아가 보통 제일 저렴) |

> **💡 US-East-1 (미국 버지니아 북부):**  
> AWS 최초의 리전이며, IAM·CloudFront·Billing 같은 **글로벌 서비스의 메인 거점**입니다.  
> AWS 콘솔에서 "글로벌" 서비스를 설정할 때 내부적으로 us-east-1을 사용합니다.

## 가용 영역 (Availability Zone, AZ)

> **정의:** 리전 내부를 나눈 단위. 하나 이상의 실제 데이터센터 건물로 구성됨

> **비유:** 서울 리전이 "서울특별시"라면, 가용 영역은 **강남구, 서초구, 송파구에 각각 지어둔 데이터센터**입니다.  
> 강남구 건물에 화재가 나도, 서초구·송파구 건물은 멀쩡히 돌아갑니다.

### 가용 영역의 특징

- 하나의 리전은 **최소 3개 이상의 AZ**로 구성
- AZ끼리는 재해(정전, 홍수, 화재) 대비를 위해 **물리적으로 수십 km 이상** 떨어져 있음
- 하지만 빠른 내부 통신을 위해 **100km 이내** 거리를 유지
- AZ 간에는 **전용 고속 네트워크**로 연결 (일반 인터넷보다 훨씬 빠름)

### AZ 식별자 주의사항

> **보안상 AZ 주소는 랜덤으로 배정됩니다.**

내 계정의 `ap-northeast-2a`(서울 AZ-A)와 친구 계정의 `ap-northeast-2a`는 **실제로 다른 물리적 위치**일 수 있습니다.  
AWS가 특정 AZ에 트래픽이 몰리는 것을 방지하기 위해 계정마다 AZ 매핑을 다르게 합니다.

### 왜 여러 AZ에 분산 배포할까?

```
[잘못된 설계]
모든 EC2 → AZ-A에만 배포
→ AZ-A 장애 시 전체 서비스 중단 ❌

[올바른 설계]
EC2 → AZ-A, AZ-B, AZ-C에 분산
→ AZ-A 장애 시 AZ-B, AZ-C로 자동 전환 ✅
```

> **중학생 비유:**  
> 중요한 숙제 파일을 USB 하나에만 저장하면, USB를 잃어버리면 끝입니다.  
> 구글 드라이브, 이메일, 친구 컴퓨터에 각각 백업해두면 하나가 없어져도 됩니다.  
> AZ 분산도 같은 원리입니다.

## 엣지 로케이션 (Edge Location)

> **정의:** 전 세계 수백 곳에 흩어져 있는 콘텐츠 배포 거점

> **비유:** 동네 편의점(또는 쿠팡 로켓배송 캠프)입니다.  
> 본사 창고(AWS 리전)가 서울에 있어도, 부산 사람이 주문하면 부산 편의점(엣지 로케이션)에 미리 쌓아둔 물건을 즉시 줍니다.

### 엣지 로케이션의 역할

| 서비스 | 역할 |
|---|---|
| **CloudFront (CDN)** | 이미지·영상·JS 등 정적 파일을 가까운 엣지에 캐싱해두고 빠르게 전달 |
| **Global Accelerator** | 사용자 → 가장 가까운 엣지 → AWS 백본 네트워크 → 목적지 서버로 빠르게 연결 |
| **Route 53** | DNS 쿼리를 전 세계에서 빠르게 처리 |

> **구체적인 예시:**  
> 넷플릭스가 AWS CloudFront를 쓴다고 가정하면,  
> 한국 사용자가 영화를 재생할 때 미국 본사 서버까지 데이터를 받아오는 게 아니라,  
> 서울 근처의 엣지 로케이션에 미리 캐싱된 영상을 받아옵니다 → 버퍼링 없이 즉시 재생!

## 글로벌 서비스 vs 리전 서비스

AWS 서비스는 어디를 기반으로 동작하느냐에 따라 두 종류로 나뉩니다.

| 구분 | 설명 | 예시 |
|---|---|---|
| **글로벌 서비스** | 전 세계 모든 리전에서 공통으로 사용되는 서비스 | IAM, Route 53, CloudFront, WAF |
| **리전 서비스** | 특정 리전에 종속되어 동작하는 서비스 (대부분의 AWS 서비스) | EC2, RDS, S3, Lambda, VPC |

> **비유:**  
> - 글로벌 서비스 = 회사 전체를 관리하는 **본사 인사팀** (어느 지사에서든 공통 적용)  
> - 리전 서비스 = **서울 지사 영업팀, 도쿄 지사 영업팀** (각 지사별로 독립 운영)

### 실무에서 헷갈리는 경우

```
IAM 사용자를 서울 리전에서 만들었어도, 도쿄 리전에서도 같은 계정으로 로그인 가능
→ IAM은 글로벌 서비스이기 때문

EC2를 서울 리전에서 만들면, 도쿄 리전 콘솔에서는 보이지 않음
→ EC2는 리전 서비스이기 때문
```

## ARN (Amazon Resource Name)

> **정의:** AWS의 모든 리소스에 부여되는 전 세계에서 유일한 고유 식별자

> **비유:** AWS 리소스의 주민등록번호이자 정확한 주소입니다.  
> "서울 강남구 테헤란로 123번지 101호"처럼, ARN을 보면 이 리소스가 **어느 계정의, 어느 리전의, 어떤 서비스의, 어떤 자원인지** 정확히 알 수 있습니다.

### ARN 형식

```
arn:[partition]:[service]:[region]:[account_id]:[resource_type]/resource_name
```

### 실제 예시

```
arn:aws:s3:::my-bucket
→ AWS의 S3 서비스에 있는 'my-bucket'이라는 버킷

arn:aws:ec2:ap-northeast-2:123456789012:instance/i-0abc1234
→ 계정 123456789012의 서울 리전(ap-northeast-2) EC2 인스턴스

arn:aws:iam::123456789012:user/hjwoo
→ 계정 123456789012의 IAM 사용자 'hjwoo' (IAM은 글로벌이라 region 자리가 비어있음)
```

### ARN이 왜 필요할까?

IAM 정책에서 "특정 S3 버킷에만 접근 허용"을 설정할 때처럼, **정확히 어떤 리소스를 가리키는지** 명시해야 할 때 사용합니다.

```json
{
  "Effect": "Allow",
  "Action": "s3:GetObject",
  "Resource": "arn:aws:s3:::my-bucket/*"
}
```

> 이 정책은 "my-bucket 안의 파일 읽기만 허용"이라는 뜻입니다.

## 전체 구조 한눈에 보기

```
전 세계
├── 리전 (Region) — 국가/대륙 단위 거점
│   ├── 가용 영역 AZ-A — 실제 데이터센터 건물 1개 이상
│   ├── 가용 영역 AZ-B
│   └── 가용 영역 AZ-C
│
└── 엣지 로케이션 (Edge Location) — 전 세계 수백 곳의 CDN 거점
```

> **중학생 비유로 최종 정리:**  
> - **리전** = 서울·도쿄·뉴욕에 있는 AWS 본 지점  
> - **가용 영역** = 같은 도시 안에서 강남·서초·송파에 각각 따로 지은 건물  
> - **엣지 로케이션** = 동네마다 있는 편의점 (자주 쓰는 것들을 미리 가져다 놓은 곳)
