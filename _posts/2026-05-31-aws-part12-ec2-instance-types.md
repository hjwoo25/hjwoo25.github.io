EC2를 처음 접하면 `c7gn.xlarge`, `r6i.2xlarge` 같은 이름에 당황하게 됩니다.  
하지만 이 이름에는 명확한 규칙이 있고, 규칙만 알면 이름만 봐도 어떤 서버인지 파악할 수 있습니다.  
이번 글에서는 **인스턴스 명명 규칙**과 **인스턴스 패밀리**를 정리합니다.

---

## 인스턴스란?

> **비유:** EC2가 아파트 단지라면, 인스턴스는 그 안의 **개별 세대(집)** 입니다.

인스턴스는 EC2 내에서 **실제 연산(컴퓨팅)을 담당하는 단위**입니다.

| 구성 요소 | 역할 | 비유 |
|---|---|---|
| **인스턴스** | CPU + 메모리로 연산 처리 | 집에 사는 사람 (거주자) |
| **EBS** | 데이터 저장 (가상 하드드라이브) | 창고 (수납 공간) |
| **네트워크** | 인스턴스와 EBS를 연결 | 집과 창고를 잇는 통로 |

**중요한 제약:**  
인스턴스는 반드시 **하나의 가용영역(AZ) 안에** 존재해야 합니다.  
(같은 리전이라도 서울 AZ-a의 인스턴스는 서울 AZ-c의 EBS에 바로 붙을 수 없음)

---

## 인스턴스 명명 규칙

`c7gn.xlarge`를 예시로 각 파트를 분해해봅니다.

```
c   7   g n  .  xlarge
│   │   │ │     └── 인스턴스 크기
│   │   │ └──────── 추가 기능 (n: 네트워크 최적화)
│   │   └────────── 프로세서 종류 (g: Graviton)
│   └────────────── 세대 (숫자가 높을수록 최신)
└────────────────── 인스턴스 패밀리 (c: 컴퓨팅 최적화)
```

### 파트별 설명

| 위치 | 의미 | 예시 |
|---|---|---|
| **패밀리** | 인스턴스의 목적/특성 | `c` (컴퓨팅), `r` (메모리), `g` (GPU) |
| **세대** | 숫자가 높을수록 최신 세대 | `7` → 7세대 |
| **프로세서** | 사용 CPU 종류 | `g` = Graviton(ARM), `a` = AMD, 없으면 Intel |
| **추가 기능** | 특화 기능 | `n` = 네트워크 최적화, `d` = 로컬 NVMe SSD 내장 |
| **크기** | 성능 규모 | nano < micro < small < medium < large < xlarge < 2xlarge ... |

> **💡 크기(Size)와 성능의 관계:**  
> 크기가 클수록 **CPU, 메모리, 네트워크 대역폭, EBS 통신 대역폭** 모두 비례해서 증가합니다.  
> `c7g.xlarge`는 `c7g.large`보다 CPU와 메모리가 2배입니다.

## 인스턴스 패밀리 (유형) 5가지

목적에 맞는 서버를 고르는 것이 비용과 성능 모두를 최적화하는 핵심입니다.

### ① 범용 (General Purpose) — `t, m, A1, Mac`

> **비유:** 만능 선수. 어느 포지션이든 무난하게 소화하는 올라운더입니다.

- CPU, 메모리, 네트워크 성능이 균형 잡혀 있음
- 특별히 한 가지가 튀어나오지 않아도 되는 **일반 워크로드**에 적합

**주요 사용처:**
- 저렴한 웹서버
- 소규모 데이터베이스
- 개발/테스트 환경
- ARM 기반 워크로드 (A1), Mac 빌드 환경 (Mac)

```
t3.micro → 프리티어 포함, 가장 저렴한 웹서버 구성에 자주 사용 ✅
```

---

### ② 컴퓨팅 최적화 (Compute Optimized) — `C`

> **비유:** 단거리 100m 달리기 선수. CPU 성능 하나만큼은 압도적입니다.

- **CPU 집약적** 작업에 특화
- 같은 비용 대비 CPU 코어 수와 클럭 속도가 다른 패밀리보다 높음

**주요 사용처:**
- 고성능 웹서버 / API 서버
- CPU 성능이 병목인 배치 처리
- 게임 서버
- 과학적 모델링, 미디어 트랜스코딩

---

### ③ 메모리 최적화 (Memory Optimized) — `r, X, z`

> **비유:** 광대한 작업 책상을 가진 사람. 한꺼번에 엄청난 양의 데이터를 펼쳐놓고 작업합니다.

- **대용량 메모리**를 필요로 하거나 메모리 성능이 중요한 워크로드 전용
- RAM 용량이 일반 인스턴스 대비 압도적으로 크고 가성비가 좋음

**주요 사용처:**
- 대규모 인메모리 데이터베이스 (Redis, Memcached)
- 실시간 빅데이터 처리 (Apache Spark)
- SAP HANA 같은 고메모리 요구 ERP 시스템

---

### ④ 가속 컴퓨팅 (Accelerated Computing) — `f, Inf, g, p`

> **비유:** CPU라는 만능 일꾼 대신, 한 가지 일만 초고속으로 처리하는 **전문 기계**를 투입합니다.

- GPU, FPGA, 추론 칩 등 **하드웨어 가속기**를 탑재
- 범용 CPU로는 감당하기 어려운 병렬 연산에 특화

**주요 사용처:**

| 타입 | 주요 용도 |
|---|---|
| `g` (GPU) | 머신러닝 학습, 3D 시각화, 비디오 스트리밍 |
| `p` (GPU, 고성능) | 딥러닝 모델 학습, HPC (고성능 컴퓨팅) |
| `Inf` (Inferentia) | AI 추론 최적화 (학습이 아닌 서빙 단계) |
| `f` (FPGA) | 게놈 분석, 금융 알고리즘, 실시간 비디오 처리 |

---

### ⑤ 저장 최적화 (Storage Optimized) — `h, i, d`

> **비유:** 초고속 물류창고. 데이터를 읽고 쓰는 속도 자체가 경쟁력입니다.

- **디스크 I/O 속도와 처리량(쓰루풋)** 최적화
- 로컬 NVMe SSD를 직접 장착하여 네트워크 지연 없이 초고속 접근

**주요 사용처:**
- 분산 파일시스템 (Hadoop HDFS)
- NoSQL 데이터베이스 (Cassandra, MongoDB)
- 데이터 웨어하우스
- 대규모 트랜잭션 처리 DB

---

## 패밀리 비교 요약

| 카테고리 | 타입 | 핵심 강점 | 대표 사용처 |
|---|---|---|---|
| 범용 | t, m, A1, Mac | 균형 잡힌 성능 | 웹서버, 개발환경 |
| 컴퓨팅 최적화 | C | CPU 집중 | 게임서버, 배치 처리 |
| 메모리 최적화 | r, X, z | 대용량 RAM | 인메모리 DB, Spark |
| 가속 컴퓨팅 | f, Inf, g, p | GPU/FPGA 가속 | 머신러닝, 3D |
| 저장 최적화 | h, i, d | 디스크 I/O | Hadoop, NoSQL |
