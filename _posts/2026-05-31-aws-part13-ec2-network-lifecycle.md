## ENI (Elastic Network Interface)

> **정의:** VPC에서 가상 네트워크 카드를 나타내는 논리적 네트워킹 구성 요소

> **비유:** EC2가 컴퓨터 본체라면, ENI는 그 본체에 꽂혀 있는 **랜카드**입니다.  
> 랜카드를 바꾸면 IP와 MAC 주소가 바뀌는 것처럼, ENI를 교체하면 네트워크 정보가 통째로 이동합니다.

### ENI의 핵심 특성

| 특성 | 내용 |
|---|---|
| **보유 정보** | IP 주소, MAC 주소 |
| **복수 연결** | 하나의 인스턴스에 여러 ENI 부착 가능 → 한 인스턴스가 여러 IP 보유 |
| **기본 IP 유형** | Private IP + Private 도메인 기본 보유 |
| **선택적 부여** | Public IP + Public 도메인은 선택적으로 부여 |

### 보안 그룹은 ENI에 붙는다

"보안 그룹이 EC2에 붙는다"고 이해하기 쉽지만, 정확히는 **ENI에 부착**됩니다.

```
[정확한 구조]
EC2 인스턴스
  └── ENI (랜카드) ← 보안 그룹이 여기에 부착
        ├── IP 주소
        └── MAC 주소
```

ENI를 다른 인스턴스로 옮기면 **보안 그룹 설정도 함께 이동**합니다.

### ENI 활용 시나리오 — 장애 대응

```
인스턴스 A (장애 발생)
  └── ENI-1 (고정 IP: 10.0.0.10)

  ↓ ENI-1을 분리해서 인스턴스 B에 부착

인스턴스 B (정상)
  └── ENI-1 (고정 IP: 10.0.0.10) ← 동일 IP로 트래픽 계속 수신 ✅
```

## Elastic IP (탄력적 IP)

> **정의:** EC2의 퍼블릭 IP를 **고정**해주는 서비스

> **비유:** 일반 퍼블릭 IP가 임시 숙소(이사할 때마다 주소가 바뀜)라면,  
> Elastic IP는 **내 소유의 집 주소**입니다. 어느 인스턴스로 이사해도 주소는 그대로입니다.

### 왜 필요한가?

```
[Elastic IP 없이]
EC2 시작 → 퍼블릭 IP: 54.100.200.1
EC2 중지
EC2 재시작 → 퍼블릭 IP: 13.209.100.55 (변경됨!)

→ DNS에 등록해둔 IP가 틀려져서 서비스 접속 불가 ❌

[Elastic IP 사용]
EC2 중지 → 재시작해도 항상 같은 IP 유지 ✅
```

### Elastic IP의 주요 특성

| 특성 | 내용 |
|---|---|
| **적용 대상** | EC2뿐 아니라 NLB 등 다른 AWS 서비스에도 사용 가능 |
| **관리 단위** | 리전(Region) 단위로 생성 및 관리 |
| **기본 제공** | 계정당 리전별 기본 5개 |

> **⚠️ 주의:** Elastic IP를 할당받아 놓고 EC2에 **연결하지 않은 채** 보유만 하면 **비용이 발생**합니다.  
> 사용하지 않는 Elastic IP는 반드시 해제(Release)할 것!

### ENI와 Elastic IP의 관계

```
EC2 인스턴스
  └── ENI (랜카드)
        ├── Private IP (항상 고정)
        ├── Public IP (중지/재시작 시 변경)
        └── Elastic IP (선택적 연결, 영구 고정)
```

## EC2 생명 주기 (Lifecycle)

> **비유:** EC2 인스턴스는 컴퓨터처럼 켜고, 끄고, 재부팅하고, 완전히 버릴 수 있습니다.  
> 상태에 따라 요금이 나가는지 여부가 다릅니다.

### 상태별 설명과 요금

| 상태 | 설명 | 인스턴스 요금 |
|---|---|---|
| **pending** | running 상태가 되기 위해 준비 중 | 미청구 |
| **running** | 정상적으로 부팅되어 사용 중 | **청구** |
| **stopping** | 중지 또는 최대 절전 모드로 전환 중 | 미청구 (최대 절전 시 청구) |
| **stopped** | 완전히 중지된 상태, 재시작 가능 | 미청구 |
| **shutting-down** | 영구 삭제를 위해 정리 중 | 미청구 |
| **terminated** | 영구적으로 삭제된 상태 | 미청구 |

> **💡 핵심:** `running` 상태일 때만 인스턴스 요금이 청구됩니다.  
> 하지만 `stopped` 상태에서도 **EBS 볼륨, Elastic IP**는 요금이 계속 나옵니다.

### 중지 vs 재부팅 vs 최대 절전 비교

| 구분 | 일반 중지 | 재부팅 | 최대 절전 |
|---|---|---|---|
| 퍼블릭 IP | 재시작 시 변경 | 유지 | 재시작 시 변경 |
| RAM 내용 | 삭제 | 유지 | EBS에 보존 |
| 재시작 속도 | 전체 부팅 | 해당 없음 | 빠른 복귀 |
| stopping 요금 | 미청구 | 해당 없음 | 청구 |

## EC2 접속 방법 4가지

### ① SSH 연결

가장 기본적인 원격 접속 방식으로, **SSH 키 페어**로 인증합니다.

```bash
ssh -i "my-key.pem" ec2-user@<퍼블릭-IP>
```

| 항목 | 내용 |
|---|---|
| **인증 방식** | SSH 키 페어 (프라이빗 키 파일) |
| **필요 조건** | 인터넷 연결, 퍼블릭 서브넷, 보안 그룹 22포트 오픈 |
| **기본 유저명** | Amazon Linux: `ec2-user` / Ubuntu: `ubuntu` |

> **⚠️ 주의:** 키 페어는 최초 생성 시 1회만 다운로드 가능합니다.

---

### ② FTP 연결

- **파일 전송** 전용 방식 (SFTP 기준)
- SSH 키 페어로 인증, 인터넷 연결 필요

---

### ③ EC2 인스턴스 연결 (Instance Connect)

> **비유:** 경비원(AWS)이 임시 출입증을 발급해줍니다.

- AWS 콘솔에서 버튼 하나로 접속 가능 **(브라우저 기반 SSH)**
- **임시 SSH 키**를 생성해서 EC2로 자동 주입 후 연결
- **IAM 인증** 사용 → AWS 계정 권한으로 접근 제어
- **CloudTrail**을 통해 누가 언제 접속했는지 감사 기록 가능

```
장점: 키 파일(.pem) 관리 불필요, 브라우저에서 바로 접속 ✅
단점: 퍼블릭 서브넷이거나 Instance Connect Endpoint 설정 필요
```

---

### ④ EC2 직렬 콘솔 (Serial Console)

> **비유:** 서버에 모니터와 키보드를 직접 꽂고 조작하는 것과 동일합니다.

- 네트워크 없이도 인스턴스에 접근 가능
- **부팅 문제, 네트워크 설정 오류** 등 일반 SSH로는 접속이 안 되는 상황에서 유용

| 항목 | 내용 |
|---|---|
| **인증 방식** | IAM 인증 + OS Root Password |
| **용도** | 부팅 실패, 네트워크 설정 오류 디버깅 |

---

## 접속 방법 비교

| 방법 | 인증 | 인터넷 필요 | 주요 용도 |
|---|---|---|---|
| SSH 연결 | SSH 키 페어 | ✅ | 일반 원격 관리 |
| FTP 연결 | SSH 키 페어 | ✅ | 파일 전송 |
| Instance Connect | IAM | ✅ (또는 Endpoint) | 키 없이 빠른 접속, 감사 필요 시 |
| 직렬 콘솔 | IAM + Root PW | ❌ | 부팅/네트워크 장애 복구 |
