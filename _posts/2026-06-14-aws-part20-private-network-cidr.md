IP 주소는 무한하지 않습니다. 약 43억 개뿐인 IPv4 주소를 효율적으로 나눠 쓰기 위해 등장한 사설망, NAT, CIDR 개념을 빠짐없이 정리합니다.

---

## 사설망(Private Network)의 등장 배경

> **비유:** 회사 내선 전화 시스템입니다.  
> 43억 개의 직통 전화번호(공인 IP)는 전 세계 인구가 쓰기에 턱없이 부족합니다.  
> 그래서 회사 안에서는 외부에서 걸 수 없는 '내선 번호(사설 IP)'를 자기들끼리 쓰고,  
> 외부로 전화를 걸 때는 회사의 '대표 전화번호(Gateway가 가진 공인 IP)'로 변환되어 나가는 것입니다.

사설망은 전 세계적으로 한정된 IP 주소를 최대한 아껴서 활용하기 위해 IP를 분할하고자 만들어진 개념입니다.

### 왜 IP가 부족할까?

- 우리가 흔히 쓰는 **IPv4** 방식은 최대 IP 개수가 약 **43억 개(4,294,967,296개)**로 한정되어 있습니다.
- 참고로 새로운 주소 체계인 **IPv6**는 IP 개수가 무려 **2^128개**로 무한대에 가까워 사설망이라는 꼼수 자체가 필요 없습니다.

### 어떻게 작동할까?

- 사설망 내부에 있는 기기들은 외부 인터넷 망과 **직접 통신이 불가능한 '사설 IP'**로 이루어져 있습니다.
- 하나의 사설망은 **사설 IP를 부여받은 여러 기기들**과, 외부 통신을 도와주는 **'Gateway'**로 구성됩니다.

### 외부와 통신할 때

- 기기들이 인터넷과 통신할 때는 반드시 **Gateway를 거쳐**, 외부 통신이 가능한 **'공인 IP'**를 하나로 공유하거나 나누어 사용하게 됩니다.
- 아무 IP나 막 쓰는 것이 아니라 **지정된 대역의 아이피만** 사설 IP로 사용할 수 있습니다.

## NAT (Network Address Translation): 주소 변환의 3가지 방식

NAT는 사설 IP를 가진 내부 기기가 외부 인터넷망과 통신할 수 있도록, **사설 IP를 공인 IP로 변환해 주는 기술**입니다. 변환 방식에 따라 딱 3가지로 나뉩니다.

> **비유:** 택배 발송 대행입니다.
> - **Dynamic NAT:** 빈 택배 박스 아무거나 골라서 회사 스티커를 붙임
> - **Static NAT:** 김대리 전용 회사 스티커가 고정되어 있음
> - **PAT:** 택배 박스는 회사 대표 스티커 딱 1장만 쓰되, 옆에 '작업번호 50001', '작업번호 50002'를 적어서 나중에 누구 물건인지 구분함

### 1) Dynamic NAT (동적 NAT)

1개의 사설 IP를, 미리 준비된 **공인 IP 그룹(NAT Pool)**에서 현재 남는 아무 공인 IP에 무작위로 연결해 줍니다.

**예시:** 사설 `192.168.0.2`가 통신을 요청하면, NAT Pool에 있던 `181.227.3.53`이라는 공인 IP를 임시로 꺼내서 변환해 주고 목적지(`61.123.44.1`)로 보냅니다.

### 2) Static NAT (정적 NAT)

1개의 사설 IP를 항상 **고정된 1개의 공인 IP로만 1:1 연결**합니다. **AWS의 Internet Gateway**가 바로 이 방식을 씁니다.

**예시:** 사설 `192.168.0.2`는 무조건 공인 `181.227.3.33`으로만 변환됩니다.

### 3) PAT (Port Address Translation)

많은 사설 IP를 **단 1개의 공인 IP**로 묶어서 연결하는 방식입니다. **AWS의 NAT Gateway**나 **NAT Instance**가 이 방식을 씁니다.

- **어떻게 구분할까?** IP는 1개지만 **'포트(Port)' 번호**를 다르게 붙여서 데이터를 구분합니다.
- **예시:** 사설 `192.168.0.2`(포트 5000)는 공인 IP의 **포트 50001번**으로 매핑(SRC port)되고, 다른 사설 기기인 `192.168.0.5`(포트 5000)는 공인 IP의 **포트 50002번**으로 매핑되어 한 공인 IP(`181.227.3.33`)를 같이 씁니다.

### NAT 방식 비교 정리

| 방식 | 매핑 | 사설 IP : 공인 IP | AWS 활용 |
|---|---|---|---|
| **Dynamic NAT** | 무작위 (Pool에서 남는 것) | 1:1 (유동적) | — |
| **Static NAT** | 고정 1:1 | 1:1 (고정) | Internet Gateway |
| **PAT** | 포트 번호로 구분 | N:1 | NAT Gateway / NAT Instance |

## 사설망 IP의 3가지 클래스(Class) 대역

아무 주소나 사설망으로 쓸 수 있는 것은 아닙니다. 전 세계가 약속한 특정 IP 범위만 사설망으로 쓸 수 있으며, 규모에 따라 A, B, C 클래스로 나뉩니다.

| 클래스 | IP 범위 | 블록 크기 | 서브넷 마스크 | IP 개수 |
|---|---|---|---|---|
| **Class A** (가장 거대) | `10.0.0.0` ~ `10.255.255.255` | 24-bit block | `255.0.0.0` | 약 **16,777,216**개 |
| **Class B** (중간 규모) | `172.16.0.0` ~ `172.31.255.255` | 20-bit block | `255.240.0.0` | 약 **1,048,576**개 |
| **Class C** (가장 작음) | `192.168.0.0` ~ `192.168.255.255` | 16-bit block | `255.255.0.0` | **65,536**개 |

## CIDR (Classless Inter-Domain Routing)과 이진수 계산

IP 주소의 영역을 여러 개의 네트워크로 마음대로 나누고 묶기 위한 **표기법이자 방식**입니다.

### 표기법

**`A.B.C.D/E`** 형식을 씁니다 (예: `10.0.1.0/24`, `172.16.0.0/12`).

- 앞의 `A.B.C.D`는 **네트워크+호스트 주소**를 나타냅니다.
- 뒤의 `E` (0~32 범위)는 이 전체 32비트 중 **'네트워크 주소'가 몇 비트인지**를 표시합니다.

### 보유 가능한 IP 개수 계산법

IPv4는 총 **32비트**입니다. 호스트 주소 비트만큼 IP를 가질 수 있습니다.

```
호스트 비트 = 32 - 네트워크 비트(E)
보유 IP 개수 = 2^(호스트 비트)
```

**예시:** `192.168.2.0/24`

- 네트워크 비트 = **24**
- 호스트 비트 = 32 - 24 = **8비트**
- 보유 IP = 2^8 = **256개** (`192.168.2.0` ~ `192.168.2.255`)

### 연습문제 해부: `10.88.135.144/28`

이를 컴퓨터가 인식하는 이진수로 풀면:

```
10       →  00001010
88       →  01011000
135      →  10000111
144      →  10010000

합치면: 00001010.01011000.10000111.10010000
        ├──── 앞 28비트: 네트워크 주소 (고정) ────┤├─ 4비트: 호스트 ─┤
```

- 앞에서부터 **28비트**까지가 고정된 **'네트워크 주소'**
- 나머지 끝의 **4비트**만 우리가 쓸 수 있는 **'호스트 주소'**
- 보유 IP = 2^4 = **16개**

## 서브넷(Subnet)

서브넷은 **'네트워크 안의 네트워크'**로, 큰 IP 네트워크 범위를 조금씩 잘라 더 작은 단위로 나눈 것을 뜻합니다.

> **비유:** 건물 층별 분양입니다.  
> 큰 땅(네트워크)을 1층, 2층(서브넷)으로 나누어 임대를 줍니다.

**예시:** `192.168.0.0/16`이라는 큰 네트워크를, Gateway를 각각 두어 서브넷으로 쪼개어 쓸 수 있습니다.

```
192.168.0.0/16 (큰 네트워크)
├── 서브넷 1: 192.168.1.0/24
├── 서브넷 2: 192.168.2.0/24
└── 서브넷 3: 192.168.3.0/24
```

## AWS 서브넷의 5개 예약 IP 규칙

> **비유:** 각 층에 256평의 공간이 나왔다고 해서 256평 모두 상가를 차릴 수는 없습니다.  
> AWS라는 건물주의 법칙에 따라 화장실(Router), 비상구(DNS), 엘리베이터(네트워크 주소) 등 공용 시설로 쓸 **5평은 무조건 비워두고**, 남은 **251평**만 세입자가 자유롭게 쓸 수 있습니다.

AWS에서 서브넷을 만들어 IP를 할당할 때, 계산된 총 IP 개수에서 **무조건 5개를 제외**하고 써야 합니다.

**예시:** `10.0.0.0/24` 대역 (원래 2^8 = 256개) → 실제 사용 가능한 IP는 **251개 (256 - 5)**

| 예약된 IP | 용도 |
|---|---|
| `10.0.0.0` | **네트워크 어드레스** — 해당 네트워크 대역 자체를 지칭 |
| `10.0.0.1` | **VPC Router** — 네트워크 안에서 길을 안내하는 내부 장비용 |
| `10.0.0.2` | **DNS Server** — 도메인 주소를 변환해 주는 장비용 |
| `10.0.0.3` | **AWS 예약** — 미래에 쓰려고 예약해 둔 예비용 주소 |
| `10.0.0.255` | **브로드캐스트 어드레스** — AWS는 브로드캐스트를 지원하지 않지만 규칙상 점유 |
