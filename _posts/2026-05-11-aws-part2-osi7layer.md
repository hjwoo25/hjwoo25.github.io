## OSI 7 계층이란?

> **비유:** 편지를 보내는 과정을 생각해 봅시다.  
> 편지를 써서(내용) → 봉투에 넣고(포장) → 우체통에 넣고(운반) → 집배원이 분류하고(경로) → 상대방 우체통에 도달하고(전달) → 상대방이 봉투를 열어(해석) → 편지를 읽는(이해) 것처럼  
> 인터넷에서 데이터를 주고받는 과정도 7단계로 나뉩니다.

OSI(Open Systems Interconnection) 모델은 서로 다른 시스템이 통신하는 방법을 **7개의 계층(Layer)**으로 정리한 표준 모델입니다.

> **암기 팁:** **P**lease **D**o **N**ot **T**hrow **S**ausage **P**izza **A**way  
> (Physical → Data Link → Network → Transport → Session → Presentation → Application)

| 계층 | 이름 | 역할 | 단위 | 장비 |
|---|---|---|---|---|
| 7 | Application (응용) | 사용자와 직접 상호작용 | Data | - |
| 6 | Presentation (표현) | 데이터 포맷·암호화 | Data | - |
| 5 | Session (세션) | 연결 유지 및 관리 | Data | - |
| 4 | Transport (전송) | 신뢰성·포트 관리 | Segment | - |
| 3 | Network (네트워크) | IP 주소·라우팅 | Packet | 라우터 |
| 2 | Data Link (데이터 링크) | MAC 주소·충돌 방지 | Frame | 스위치 |
| 1 | Physical (물리) | 전기 신호·케이블 | Bit | 허브 |

> 💡 실무에서는 OSI 7계층보다 **TCP/IP 4계층**을 더 많이 사용합니다.  
> (Network Access → Network → Transport → Application으로 통합)

---

## Layer 1. Physical Layer (물리 계층)

> **비유:** 두 사람이 통화하려면 전화선(또는 무선 전파)이 있어야 합니다. 물리 계층은 바로 이 "전선"에 해당합니다.

- 장치를 연결하는 **물리적 매체**(케이블, 전압, 안테나 규격 등)를 정의합니다.
- 데이터를 0과 1의 전기 신호(비트)로 변환하여 전송합니다.
- **단위:** Bit
- **장비:** 허브(Hub) — 받은 신호를 연결된 모든 포트에 그냥 뿌림 (확성기 역할, 충돌 방지 기능 없음)

---

## Layer 2. Data Link Layer (데이터 링크 계층)

> **비유:** 아파트 같은 동에 사는 주민들끼리 내선 전화를 쓰는 것과 같습니다.  
> 같은 네트워크(아파트) 안에서 서로를 구분하는 번호가 바로 **MAC 주소**입니다.

- 물리적 통신을 제어하여 **같은 네트워크 안에서의 통신을 안정화**합니다.
- **단위:** Frame
- **장비:** 스위치(Switch) — MAC 주소 테이블을 보고 해당 포트로만 데이터를 전달 (충돌 방지)

### MAC Address

- 네트워크 인터페이스 카드(NIC)에 새겨진 **고유 식별 번호** (48비트, 예: `AA:BB:CC:DD:EE:FF`)
- 주민등록번호처럼 **변하지 않는 고유값**입니다.
- IPv4 주소는 바뀔 수 있지만, MAC 주소는 제조사가 하드웨어에 새겨둡니다.

### 한계

같은 건물(로컬 네트워크) 안에서만 통신 가능합니다. 다른 건물(외부 네트워크)과 통신하려면 Layer 3이 필요합니다.

---

## Layer 3. Network Layer (네트워크 계층)

> **비유:** 전국 택배 시스템과 같습니다.  
> 서울에서 부산까지 택배를 보낼 때, 여러 물류 센터를 거쳐 최적 경로로 도착하듯이 — 라우터가 패킷을 최적 경로로 전달합니다.

- **서로 다른 네트워크 간 통신**을 담당합니다.
- **단위:** Packet (패킷)
- **장비:** 라우터(Router)

### IP Address

- 통신 주체를 식별하는 **논리적 주소** (MAC 주소와 달리 수시로 변경 가능)
- `IPv4`: 32비트 (예: 192.168.1.1) — 주소 고갈 문제로 공인/사설 IP로 구분
- `IPv6`: 128비트 — 사실상 무한에 가까운 주소 제공

> **공인 IP vs 사설 IP:**  
> 공인 IP = 집 주소 (전국에서 유일)  
> 사설 IP = 집 안의 방 번호 (우리 집 안에서만 유효)

### CIDR 표기법 (IP 주소의 범위 표현)

```
형식: A.B.C.D/E
예시: 192.168.2.0/24
```

`/24`는 "앞 24비트가 네트워크 주소"를 의미합니다.  
→ 나머지 8비트(32-24=8)가 호스트 주소 → 2⁸ = 256개의 IP 사용 가능

| CIDR | 사용 가능한 IP 수 |
|---|---|
| /32 | 1개 (단일 IP) |
| /24 | 256개 |
| /16 | 65,536개 |
| /8 | 16,777,216개 |

### 서브넷 마스크 (Subnet Mask)

IP 주소에서 어디까지가 네트워크 비트이고, 어디부터가 호스트 비트인지 구분해줍니다.

```
IP:           192.168.2.122  →  11000000.10101000.00000010.01111010
서브넷 마스크: 255.255.255.0  →  11111111.11111111.11111111.00000000
AND 연산 결과: 192.168.2.0   →  같은 네트워크인지 판단
```

### 라우터 (Router)

- 여러 네트워크 간에 패킷을 전달하는 Layer 3 핵심 장치입니다.
- **라우팅 테이블**: 목적지 IP 대역별 최적 경로를 기록한 표입니다.
- 목적지 IP가 내부 네트워크가 아니라면, 패킷을 라우터로 전달합니다.

### ARP (Address Resolution Protocol)

> **비유:** "이 건물에서 '홍길동' 씨 어디 계세요?"라고 크게 외치면, 홍길동 씨가 "저 여기요!"라고 대답하는 것과 같습니다.

- **IP(논리 주소)로 MAC 주소(물리 주소)를 알아내는 프로토콜**입니다.
- 브로드캐스트 방식으로 "이 IP를 가진 사람 MAC 주소 알려줘!"라고 요청합니다.
- 응답받은 MAC 주소는 ARP 테이블에 저장해 재사용합니다.

### 💡 전체 흐름: 데이터가 라우터까지 전달되는 과정

```
① 서브넷 마스크로 목적지가 같은 네트워크인지 확인
② 다른 네트워크라면 → 패킷을 라우터로 보내야 함
③ 라우터 IP는 알지만 MAC 주소를 모름 → ARP 실행
④ ARP로 알아낸 라우터 MAC 주소로 프레임 생성 → 전달
```

### 한계

- 한 번에 하나의 통신만 가능 (여러 앱 동시 통신 불가)
- 패킷 순서 보장 안됨, 유실 대응 불가

→ 이 문제는 Layer 4의 **TCP**가 해결합니다!

## Layer 4. Transport Layer (전송 계층)

> **비유:** 택배 회사의 배송 서비스 종류와 같습니다.  
> **TCP = 등기 택배** (수령 확인, 분실 시 재발송, 느리지만 확실)  
> **UDP = 일반 우편** (빠르지만 분실해도 확인 안 함)

- 통신 주체끼리 데이터 전달의 **신뢰성을 확보**합니다.
- **단위:** Segment

### TCP (Transmission Control Protocol)

- **연결 지향적**: 데이터를 보내기 전에 연결을 먼저 수립합니다.
- 패킷 순서와 무결성을 보장합니다 (비교적 느림).
- **사용처:** 웹(HTTP/HTTPS), 이메일, 파일 전송 등 **신뢰성이 중요한 곳**

**TCP 3-way Handshake** (연결 수립 과정):

```
클라이언트 ──── SYN ────────► 서버
클라이언트 ◄─── SYN-ACK ──── 서버
클라이언트 ──── ACK ────────► 서버
             (연결 수립 완료!)
```

- **SYN:** "나 연결하고 싶어!"
- **SYN-ACK:** "좋아, 나도 준비됐어!"
- **ACK:** "알겠어, 이제 보내자!"

### UDP (User Datagram Protocol)

- **비연결형(Connectionless)**: 연결 확립 없이 바로 데이터를 보냅니다.
- 패킷 순서·무결성 체크 없음 → 빠름, 단 패킷 유실 가능성 있음
- **사용처:** 스트리밍, 온라인 게임, DNS (속도가 중요한 곳)

### Port (포트)

> **비유:** IP 주소가 아파트 건물 주소라면, 포트는 호수(101호, 202호)입니다.  
> 같은 컴퓨터에서도 웹 서버(80번), SSH(22번) 등 여러 서비스를 동시에 구분할 수 있습니다.

- IP 통신 위에서 **올바른 프로세스(애플리케이션)를 찾아가기 위한 번호**입니다.

| 포트 번호 | 프로토콜 | 용도 |
|---|---|---|
| 22 | SSH | 원격 서버 접속 |
| 80 | HTTP | 일반 웹 통신 |
| 443 | HTTPS | 암호화 웹 통신 |
| 3306 | MySQL | 데이터베이스 |
| 53 | DNS | 도메인 이름 조회 |

- **Well Known Port:** 0~1023번 (위처럼 용도가 정해진 포트)
- **Ephemeral Port:** 클라이언트가 서버에 접속 시 임의로 할당받는 포트 (보통 49152~65535)

## Layer 5. Session Layer (세션 계층)

> **비유:** 전화 통화에서 "여보세요"로 연결하고 "끊을게요"로 종료하는 것처럼, 세션 계층은 통신의 시작과 끝을 관리합니다.

- 통신 주체 간의 **연결(세션)을 유지하고 관리**하는 방법을 정의합니다.
- 연결이 끊겼을 때 어디서부터 다시 시작할지(체크포인트)를 관리합니다.
- **예시:** HTTP Cookie, RPC(Remote Procedure Call)

---

## Layer 6. Presentation Layer (표현 계층)

> **비유:** 한국어를 영어로 번역하거나, 음성을 문자로 변환하는 것처럼 — 데이터를 상대방이 이해할 수 있는 형태로 바꿔줍니다.

- 받은 데이터를 **해석하고 포맷팅**하는 방법을 정의합니다.
- 인코딩(UTF-8, ASCII), 암호화/복호화, 데이터 압축 등을 담당합니다.
- **예시:** SSL/TLS 암호화, JPEG/MP4 포맷 변환

---

## Layer 7. Application Layer (응용 계층)

> **비유:** 스마트폰의 카카오톡 앱이나 크롬 브라우저처럼, 사용자가 직접 눈으로 보고 조작하는 부분입니다.

- 사용자와 직접 상호작용하는 **애플리케이션 수준의 프로토콜**을 정의합니다.
- **Method, Status Code, Header** 등을 다룹니다.

| 프로토콜 | 용도 |
|---|---|
| HTTP/HTTPS | 웹 페이지 통신 |
| FTP | 파일 전송 |
| SMTP | 이메일 발송 |
| DNS | 도메인 이름 조회 |
| SSH | 원격 서버 접속 |

> **AWS와의 연계:**  
> AWS의 **ALB(Application Load Balancer)**는 Layer 7에서 동작합니다.  
> HTTP 경로(`/api/*`), 헤더, 쿠키 등을 분석해 트래픽을 지능적으로 분산할 수 있습니다.

---

## 💡 실제 예시: 크롬에서 google.com 접속 시 일어나는 일

```
[Layer 7] 크롬이 HTTP GET 요청 생성
[Layer 6] 데이터 인코딩 (UTF-8)
[Layer 5] 세션 연결 수립
[Layer 4] TCP 연결 (3-way Handshake) + 포트 지정 (출발 54321 → 목적지 443)
[Layer 3] IP 패킷 생성 (출발 내 IP → 목적지 google.com IP)
[Layer 2] MAC 주소 기반 프레임 생성
[Layer 1] 전기 신호로 변환 → 케이블/무선으로 전송
```

상대방은 이 과정을 반대로 거슬러 올라가며 데이터를 해석합니다.
