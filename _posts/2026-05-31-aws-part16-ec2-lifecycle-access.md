EC2를 운영하다 보면 "지금 중지해도 요금이 나올까?", "어떻게 접속하지?" 같은 질문이 생깁니다.  
이번 글에서는 인스턴스 상태별 요금 구조와, 인스턴스에 접속하는 4가지 방법을 정리합니다.

---

## EC2 생명 주기 (Lifecycle)

> **비유:** EC2 인스턴스는 컴퓨터처럼 켜고, 끄고, 재부팅하고, 완전히 버릴 수 있습니다.  
> 상태에 따라 돈이 나가는지 여부가 다릅니다.

### 상태별 설명과 요금

| 상태 | 설명 | 인스턴스 요금 |
|---|---|---|
| **pending** | running 상태가 되기 위해 준비 중 | 미청구 |
| **running** | 정상적으로 부팅되어 사용 중 | **청구** |
| **stopping** | 중지 또는 최대 절전 모드로 전환 중 | 미청구 (최대 절전 시 청구) |
| **stopped** | 완전히 중지된 상태, 재시작 가능 | 미청구 |
| **shutting-down** | 영구 삭제를 위해 정리 중 | 미청구 |
| **terminated** | 영구적으로 삭제된 상태 | 미청구 |

```
생명 주기 흐름:

[시작]
pending → running → stopping → stopped → (재시작) → running
                                        ↓
                              shutting-down → terminated [삭제]
```

> **💡 핵심:** `running` 상태일 때만 인스턴스 요금이 청구됩니다.  
> 하지만 `stopped` 상태에서도 **EBS 볼륨, Elastic IP**는 요금이 계속 나옵니다.

---

### 생명 주기 조작 시 알아야 할 것

#### 중지 (Stop)

- 컴퓨팅 요금은 청구되지 않음
- 연결된 **EBS 볼륨, Elastic IP**는 계속 요금 청구
- **EBS 기반 인스턴스만** 중지 가능 (인스턴스 스토어 기반은 중지 불가)
- Elastic IP 없이 중지 후 재시작하면 **퍼블릭 IP가 변경됨**

```
중지 → 재시작
퍼블릭 IP: 54.100.200.1 → 13.209.100.55 (변경!) ← Elastic IP 없으면 이렇게 됨
```

#### 재부팅 (Reboot)

- 인스턴스가 **멈추지 않은 것으로 간주**
- 퍼블릭 IP **변동 없음**
- OS 재시작만 일어나는 것과 동일한 동작

```
중지 vs 재부팅 차이:

중지(Stop) → 재시작: 퍼블릭 IP 변경 ❗
재부팅(Reboot):       퍼블릭 IP 유지 ✅
```

#### 최대 절전 모드 (Hibernate)

> **비유:** 노트북 덮개를 닫으면 RAM 내용이 그대로 보존되고, 열면 바로 이어서 쓸 수 있는 것과 같습니다.

- **메모리(RAM) 내용을 EBS에 저장**하여 재시작 시 부팅 과정 생략
- 중단된 지점부터 빠르게 시작 가능
- stopping 단계에서 **인스턴스 요금이 청구됨** (RAM 내용 저장 작업 중이기 때문)

| 구분 | 일반 중지 | 최대 절전 |
|---|---|---|
| RAM 내용 | 삭제 | EBS에 보존 |
| 재시작 속도 | 전체 부팅 | 빠른 복귀 |
| stopping 요금 | 미청구 | 청구 |

## EC2 접속 방법 4가지

EC2 인스턴스를 원격으로 제어하는 방법은 상황에 따라 4가지를 선택할 수 있습니다.

### ① SSH 연결

> **비유:** 열쇠(프라이빗 키)가 있어야 문을 열 수 있는 방식입니다.

가장 기본적인 원격 접속 방식으로, **SSH 키 페어**(프라이빗 키 + 퍼블릭 키)로 인증합니다.

```bash
ssh -i "my-key.pem" ec2-user@<퍼블릭-IP>
```

**주요 특징:**

| 항목 | 내용 |
|---|---|
| **인증 방식** | SSH 키 페어 (프라이빗 키 파일) |
| **필요 조건** | 인터넷 연결, 퍼블릭 서브넷, 보안 그룹 22포트 오픈 |
| **관리 단위** | 리전 단위 |
| **기본 유저명** | Amazon Linux: `ec2-user` / Ubuntu: `ubuntu` |

> **⚠️ 주의:** 키 페어는 최초 생성 시 1회만 다운로드 가능합니다.  
> 분실 시 EBS를 다른 인스턴스에 연결해 복구하거나, 스냅샷으로 재생성해야 합니다.

---

### ② FTP 연결

> **비유:** SSH가 터미널 원격 조작이라면, FTP는 파일만 주고받는 창구입니다.

- **파일 전송** 전용 방식
- SSH 키 페어로 인증 (SFTP 기준)
- 인터넷 연결 필요

---

### ③ EC2 인스턴스 연결 (Instance Connect)

> **비유:** 방문자가 직접 열쇠를 가져오는 게 아니라, 경비원(AWS)이 임시 출입증을 발급해줍니다.

- AWS 콘솔에서 버튼 하나로 접속 가능 (브라우저 기반 SSH)
- **임시 SSH 키**를 생성해서 EC2로 자동 주입 후 연결
- **IAM 인증** 사용 → AWS 계정 권한으로 접근 제어
- **CloudTrail**을 통해 누가 언제 접속했는지 감사 기록 가능

```
장점: 키 파일(.pem) 관리 불필요, 브라우저에서 바로 접속 ✅
단점: 퍼블릭 서브넷이거나 Instance Connect Endpoint 설정 필요
```

---

### ④ EC2 직렬 콘솔 (Serial Console)

> **비유:** 서버에 모니터와 키보드를 직접 꽂고 조작하는 것과 동일합니다.

- 네트워크 없이도 인스턴스에 접근 가능
- **부팅 문제, 네트워크 설정 오류** 등 일반 SSH로는 접속이 안 되는 상황에서 유용

**주요 특징:**

| 항목 | 내용 |
|---|---|
| **인증 방식** | IAM 인증 + OS Root Password |
| **사용 가능 조건** | 특정 인스턴스 타입만 지원 (t2 시리즈 불가) |
| **용도** | 부팅 실패, 네트워크 설정 오류 디버깅 |

---

## 접속 방법 비교

| 방법 | 인증 | 인터넷 필요 | 주요 용도 |
|---|---|---|---|
| SSH 연결 | SSH 키 페어 | ✅ | 일반 원격 관리 |
| FTP 연결 | SSH 키 페어 | ✅ | 파일 전송 |
| Instance Connect | IAM | ✅ (또는 Endpoint) | 키 없이 빠른 접속, 감사 필요 시 |
| 직렬 콘솔 | IAM + Root PW | ❌ | 부팅/네트워크 장애 복구 |
