## AWS를 배워야 하는 이유

AWS(Amazon Web Services)는 대한민국 및 글로벌 기준 점유율 1위 클라우드 프로바이더입니다.  
사용자가 많은 만큼 레퍼런스, 커뮤니티, 트러블슈팅 리소스가 방대하고, 서비스도 지속적으로 업데이트됩니다.

---

## 클라우드 컴퓨팅이란?

> **비유:** 집에서 직접 발전기를 돌리는 대신, 한국전력에서 전기를 끌어다 쓰는 것처럼 — 컴퓨팅 파워도 AWS라는 "발전소"에서 빌려다 쓰는 것입니다.

예전에는 회사마다 서버실을 직접 운영했습니다. 서버를 사고, 전기를 연결하고, 냉각 장치도 설치하고, 24시간 관리해야 했죠.  
클라우드는 이 모든 것을 AWS가 대신 해주고, 우리는 **쓴 만큼만 돈을 내는** 방식입니다.

| 구분 | 온프레미스 (직접 운영) | 클라우드 (AWS) |
|---|---|---|
| 서버 구매 | 직접 구매 (고정 비용) | 빌려 씀 (사용한 만큼) |
| 용량 조절 | 어려움 (서버 추가 구매) | 클릭 몇 번으로 즉시 확장 |
| 장애 대응 | 직접 고쳐야 함 | AWS가 인프라 관리 |

---

## AWS 서비스 공부 순서

AWS 서비스들은 긴밀하게 연결되어 있어서, 하나만 독립적으로 완벽히 이해하기 어렵습니다.  
한 서비스를 어느 정도 배운 뒤 다른 서비스를 보고, **다시 돌아와 복습하는 방식**을 추천합니다.

- **먼저 배울 것:** `EC2`, `IAM`
- **이어서 배울 것:**
  - EC2 연계: `EBS`, `ELB`, `Auto Scaling`, `Budgets`
  - 인프라 및 데이터: `VPC`, `S3`, `RDS`, `Aurora`

---

## 핵심 서비스 요약

### EC2 (Elastic Compute Cloud)

> **비유:** AWS의 거대한 컴퓨터방(PC방)에서 내 자리를 하나 빌리는 것입니다.  
> 사양(CPU, RAM, 디스크)을 골라서 빌리고, 다 쓰면 반납하면 됩니다.

- AWS에서 가장 핵심적인 **서버(컴퓨팅 파워)를 빌려주는 서비스**입니다.
- 운영체제(Linux, Windows)를 선택하고, 원하는 사양의 인스턴스를 생성할 수 있습니다.
- 필요에 따라 늘리거나 줄일 수 있어서 **탄력적(Elastic)**이라는 이름이 붙었습니다.

**EC2 주요 개념:**

| 개념 | 설명 |
|---|---|
| 인스턴스 (Instance) | 실제로 실행되는 가상 서버 1대 |
| AMI (Amazon Machine Image) | 인스턴스를 찍어내는 틀 (운영체제 + 설정 포함) |
| 인스턴스 타입 | 사양 조합 (t3.micro, m5.large 등) |
| EBS (Elastic Block Store) | EC2에 붙이는 하드디스크 (인스턴스 꺼도 데이터 유지) |
| 보안 그룹 (Security Group) | EC2에 적용되는 방화벽 규칙 (어떤 IP, 어떤 포트 허용할지) |

---

### IAM (Identity and Access Management)

> **비유:** 회사의 출입증 및 권한 시스템과 같습니다.  
> 신입사원은 사무실에만 들어갈 수 있고, 팀장은 회의실·서버실도 출입 가능하듯이 — IAM이 AWS 리소스에 대한 접근 권한을 제어합니다.

- AWS 계정의 보안과 권한을 관리하는 **글로벌 서비스**입니다.
- 어떤 사용자(사람 or 시스템)가 어떤 AWS 서비스에 접근할 수 있는지 정의합니다.

**IAM 구성 요소:**

| 구성 요소 | 설명 |
|---|---|
| 사용자 (User) | 실제 사람 or 애플리케이션에 해당하는 계정 |
| 그룹 (Group) | 여러 사용자를 묶는 단위 (예: 개발팀, 운영팀) |
| 역할 (Role) | EC2, Lambda 등 AWS 서비스가 다른 서비스에 접근할 때 사용 |
| 정책 (Policy) | "무엇을 할 수 있다/없다"는 JSON 형태의 규칙 문서 |

> **💡 핵심 원칙 — 최소 권한의 원칙 (Least Privilege):**  
> 꼭 필요한 권한만 부여합니다. 모든 계정에 관리자 권한을 주면 보안 사고 시 피해가 매우 커집니다.

---

### VPC (Virtual Private Cloud)

> **비유:** AWS 클라우드라는 거대한 건물 안에 내 회사 전용 사무실을 만드는 것입니다.  
> 다른 회사와 건물을 공유하지만, 내 사무실 안은 완전히 독립된 공간입니다.

- 클라우드 내에 생성하는 **가상의 사설 네트워크**입니다.
- EC2, RDS, Lambda 등 AWS 서비스가 실행되는 격리된 공간입니다.
- 원하는 IP 대역(CIDR)을 설정하고, 퍼블릭/프라이빗 서브넷으로 구성합니다.

```
VPC (192.168.0.0/16)
├── 퍼블릭 서브넷 (192.168.1.0/24) ← 인터넷에서 접근 가능
│   └── EC2 (웹 서버)
└── 프라이빗 서브넷 (192.168.2.0/24) ← 인터넷 직접 접근 불가
    └── RDS (데이터베이스)
```

**왜 서브넷을 나눌까요?**  
DB 서버는 외부에서 직접 접근하면 안 되니 프라이빗 서브넷에, 웹 서버는 사용자가 접속할 수 있도록 퍼블릭 서브넷에 배치합니다.

---

### S3 (Simple Storage Service)

> **비유:** 용량이 사실상 무제한인 클라우드 창고입니다.  
> 파일을 넣어두면 인터넷 어디서든 꺼낼 수 있고, 파일이 없어질 걱정도 거의 없습니다.

- **객체 스토리지(Object Storage)**: 파일 하나하나를 "객체"로 저장합니다.
- **내구성:** 99.999999999% (11 Nine) — 100억 개 파일을 저장하면 1개도 잃어버리지 않을 수준입니다.
- **가용성(Availability)과 내구성(Durability)은 다른 개념입니다:**
  - 내구성: 파일을 잃어버리지 않을 능력
  - 가용성: 원할 때 언제든 파일에 접근할 수 있는 능력

**S3 주요 용도:**

| 용도 | 설명 |
|---|---|
| 정적 웹사이트 호스팅 | HTML, CSS, JS 파일 배포 |
| 백업 및 아카이브 | DB 백업 파일, 로그 장기 보관 |
| 미디어 저장 | 이미지, 동영상 파일 저장 후 CloudFront(CDN)으로 배포 |
| 데이터 레이크 | 빅데이터 분석을 위한 원본 데이터 저장소 |

---

### RDS (Relational Database Service)

> **비유:** 데이터베이스 서버가 딸린 월셋집을 빌리는 것입니다.  
> 집주인(AWS)이 유지보수(백업, 업데이트, 장애 복구)를 해주니, 세입자(개발자)는 데이터 관리에만 집중할 수 있습니다.

- AWS가 관리해주는 **관계형 데이터베이스 서비스**입니다.
- 지원 엔진: MySQL, PostgreSQL, MariaDB, Oracle, SQL Server, **Amazon Aurora**
- 자동 백업, 암호화, 다중 가용 영역(Multi-AZ) 이중화를 지원합니다.

**EC2에 직접 DB 설치 vs RDS:**

| 구분 | EC2 직접 설치 | RDS |
|---|---|---|
| 설치/설정 | 직접 해야 함 | AWS가 해줌 |
| 백업 | 직접 설정 | 자동 지원 |
| 패치/업데이트 | 직접 관리 | AWS가 관리 |
| 비용 | 비교적 저렴 | 비교적 비쌈 |
| 유연성 | 높음 | 낮음 (AWS 정책 따름) |

## 자주 함께 쓰는 서비스들

| 서비스 | 역할 | 한 줄 비유 |
|---|---|---|
| **ELB (Elastic Load Balancer)** | 들어오는 트래픽을 여러 EC2에 골고루 분산 | 식당 입구에서 손님을 빈 자리로 안내하는 직원 |
| **Auto Scaling** | 트래픽 증가 시 EC2 자동 추가, 감소 시 자동 제거 | 손님이 많으면 알바를 더 부르고, 한산하면 귀가시키는 것 |
| **CloudWatch** | AWS 리소스 모니터링 및 알람 설정 | CPU가 90% 넘으면 문자 보내주는 알람 시스템 |
| **Route 53** | DNS 서비스 (도메인 → IP 변환) | 이름으로 전화번호를 찾아주는 전화번호부 |
| **CloudFront** | CDN 서비스 (전 세계에 빠르게 콘텐츠 배포) | 전국 각지에 물건을 미리 보내두는 물류 창고 네트워크 |
