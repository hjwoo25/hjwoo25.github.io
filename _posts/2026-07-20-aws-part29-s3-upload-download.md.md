프라이빗으로 잠겨있는 S3 파일을 외부 고객과 안전하게 공유하는 방법(Presigned URL)과, 100MB가 넘는 거대한 파일을 빠르게 업로드하는 방법(멀티파트 업로드)을 알아봅니다.

---

## 수동 파일 공유의 문제점

일반적으로 AWS 웹 콘솔이나 CLI를 통해 업로드/다운로드를 진행하지만, 외부 사용자에게 파일을 공유할 때는 인증 정보(IAM 유저의 Access Key 등)를 직접 전달해야 하는 문제가 있습니다[cite: 10]. 
이는 관리 및 유출 대처가 어렵고 만료 기간이나 세세한 권한 설정이 불가능하다는 치명적인 단점이 있습니다[cite: 10].

---

## 미리 서명된 URL (Presigned URL)

> **비유:**
> 출입이 통제된 회사 건물에 외부 손님이 올 때, 30분 뒤면 저절로 폐기되는 **'임시 QR코드 출입증'**을 카카오톡으로 보내주는 것과 같습니다.

- S3의 파일을 안전하게 공유하고 싶을 때 사용하는 **임시 URL**입니다[cite: 10].
- **URL의 만료 기간**을 지정할 수 있으며, Method(GET, PUT 등) 설정도 가능합니다[cite: 10].
- **권한 상속:** 이 URL의 권한은 **생성자가 가진 권한 중 일부 혹은 전체**를 사용합니다[cite: 10]. (예: 생성자 본인에게 다운로드(GET) 권한이 없다면, 그 사람이 만든 임시 URL로도 다운로드가 불가능함)[cite: 10].

---

## Amazon S3 멀티파트 업로드 (Multipart Upload)

> **비유:**
> 거대한 가구를 통째로 엘리베이터에 싣지 않고, 부품 단위로 분해해서 한꺼번에 옮긴 뒤 집 안에서 다시 조립하는 방식입니다.

하나의 파일을 여러 파트(예: 400MB 파일을 100MB 파트 4개)로 나누어서 업로드하는 방식입니다[cite: 10]. AWS에서는 **100MB 이상의 파일을 업로드할 경우 멀티파트 업로드를 권장**합니다[cite: 10].

| 장점 | 단점 |
|---|---|
| 업로드 속도가 빠름[cite: 10] | 단일 파트보다 업로드 로직이 복잡함[cite: 10] |
| | 중간부터 업로드하기 등 파일 컨트롤 보장이 어려움[cite: 10] |
| | 업로드에서 발생하는 파일 관리 포인트 증가[cite: 10] |

### 🚨 요금 폭탄 주의사항

- 에러 등으로 멀티파트 업로드가 중지되거나 최종적으로 합쳐지지(Complete) 않을 경우, **업로드된 파트 파일(쪼가리)들은 S3에 계속 잔류하여 보관 비용을 발생**시킵니다[cite: 10].
- **해결책:** S3 생명주기 설정을 통해 *"완료되지 않은 멀티파트 업로드의 경우 7일 후 삭제"* 와 같이 일괄 삭제 규칙을 걸어두는 것이 매우 중요합니다[cite: 10].
