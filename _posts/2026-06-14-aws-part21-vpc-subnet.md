AWS 클라우드에서 나만의 격리된 네트워크를 구축하는 핵심 서비스인 VPC와, 그 안을 목적별로 나누는 서브넷의 모든 것을 정리합니다.

---

## VPC (Virtual Private Cloud)의 모든 것

> **비유:** 클라우드라는 공공의 땅에 담장을 높게 치고 **'우리 회사 전용 데이터센터 사유지'**를 확보하는 것입니다.  
> 사유지 안의 길을 어떻게 내고(라우팅), 건물을 어디에 지을지(EC2) 온전히 내가 결정합니다.

VPC는 사용자의 AWS 계정 전용 가상 네트워크이자, 클라우드에 존재하는 **'가상의 데이터센터'**입니다.

### 기본 특징

- 다른 가상 네트워크와 **논리적으로 완벽히 분리**되어 있어 안전합니다.
- VPC는 **'리전(Region, 예: 서울 리전)' 단위**로 생성됩니다.

### 역할

- 부여된 IP 대역(CIDR)을 분할하여 원하는 대로 **사설망을 구축**할 수 있습니다.
- EC2, RDS, Lambda 등 다양한 AWS 컴퓨팅 서비스를 실행하는 공간입니다.

### 보안

- IP Block이나 인터넷에 노출되지 않는 EC2 구성 등 **강력한 보안 설정**을 할 수 있습니다.

### VPC의 핵심 구성요소 7가지

| 구성요소 | 역할 |
|---|---|
| **서브넷** | VPC의 IP를 더 작은 단위로 분할 |
| **인터넷 게이트웨이 (IGW)** | 외부 인터넷과의 연결 통로 |
| **NACL / 보안그룹** | 트래픽 제어 방화벽 |
| **라우트 테이블** | 트래픽 경로 이정표 |
| **NAT Instance / NAT Gateway** | 프라이빗 서브넷의 외부 통신 지원 |
| **Bastion Host** | 외부에서 프라이빗 서브넷 접속 경로 |
| **VPC Endpoint** | AWS 서비스와의 프라이빗 연결 |

## 서브넷 (Subnet)과 생성 규칙

> **비유:** 거대한 사유지(VPC)를 그대로 쓰면 관리가 안 되니, **'1구역(퍼블릭): 방문객용 로비'**, **'2구역(프라이빗): 직원 전용 금고'**처럼 목적에 맞게 펜스를 쳐서 땅을 나누는 것입니다.

서브넷은 VPC의 하위 단위로, VPC에 할당된 IP를 더 작은 단위로 분할한 개념입니다.

### 가용영역(AZ) 종속성

하나의 서브넷은 반드시 **'하나의 가용영역(AZ)' 안에만** 위치해야 합니다. 물리적으로 다른 데이터센터에 하나의 서브넷이 양다리를 걸칠 수 없습니다.

### 서브넷 크기 지정 (CIDR 제약)

| 프로토콜 | 최소 | 최대 |
|---|---|---|
| **IPv4** | `/28` (IP 16개, 실사용 11개) | `/16` |
| **IPv6** | `/64` | `/44` |

### AWS 서브넷 IP 개수 규칙 (5개 제외)

계산된 총 IP 개수에서 AWS가 내부적으로 사용하는 **5개의 IP는 무조건 제외**하고 계산해야 합니다.

**예시:** `10.0.0.0/24` → 256 - 5 = **251개** 사용 가능

| 예약 IP | 용도 |
|---|---|
| `10.0.0.0` | 네트워크 어드레스 |
| `10.0.0.1` | VPC Router |
| `10.0.0.2` | DNS Server |
| `10.0.0.3` | AWS 미래 예약용 |
| `10.0.0.255` | 브로드캐스트 어드레스 |

## 서브넷의 2가지 종류

### 퍼블릭 서브넷 (Public Subnet)

- 인터넷 게이트웨이(IGW)를 통해 **외부 인터넷과 연결**된 서브넷입니다.
- 안에 위치한 인스턴스에 **퍼블릭 IP를 부여**할 수 있습니다.
- **용도:** 웹서버 등 유저에게 노출되어야 하는 인프라를 배치합니다.

### 프라이빗 서브넷 (Private Subnet)

- 외부 인터넷으로 나가는 경로가 **아예 없는** 서브넷입니다.
- **퍼블릭 IP 부여가 불가능**합니다.
- **용도:** 데이터베이스나 로직 서버 등 외부 노출이 필요 없는 인프라를 보호합니다.

## VPC Router와 라우트 테이블

서브넷 간, 혹은 외부와의 통신 트래픽을 관리하는 핵심 요소입니다.

### VPC Router (가상의 라우터)

- VPC 내부에 있는 가상의 라우터로, 서브넷에서 오고 가는 **모든 트래픽은 이 라우터를 거쳐** 목적지에 도달합니다.
- VPC 생성 시 **자동으로 만들어지며** 별도의 조작이나 설정은 불가능합니다.

### 라우트 테이블 (Route Table)

자동 생성된 VPC Router에게 **"트래픽이 어디로 가야 할지 알려주는 이정표"**입니다. 라우트 테이블만 사용자가 직접 관리할 수 있습니다.

- **Destination (목적지):** 트래픽이 가고자 하는 주소 대역
- **Target (타겟):** 트래픽을 실제로 보내줄 대상 (논리적 리소스의 아이디)

### 라우트 테이블 예시

| Destination | Target | 의미 |
|---|---|---|
| `10.0.0.0/16` | `local` | VPC 내부 통신 |
| `0.0.0.0/0` | `igw-3830de61` | 모든 외부망 → 인터넷 게이트웨이로 나감 |
| `172.31.0.0/16` | `pcx-1122...` | 다른 VPC와의 연결 (VPC Peering) |

## 인터넷 게이트웨이 (Internet Gateway, IGW)

VPC가 외부의 인터넷과 통신할 수 있도록 **경로를 만들어주는 리소스**입니다.

- 기본적으로 **확장성과 고가용성**이 확보되어 있어 트래픽 병목을 방지합니다.
- **IPv4와 IPv6**를 모두 지원하며, IPv4 환경에서는 **NAT 역할**을 겸합니다.
- 생성 및 연결 **비용은 무료**이며, 반드시 **라우트 테이블에 경로를 설정**해야만 접근이 가능해집니다.

## 기본 VPC vs 커스텀 VPC

> **비유:**
> - **기본 VPC:** 문, 창문, 전기(인터넷)가 다 뚫려있는 **풀옵션 렌탈 하우스** — 들어가서 바로 쓰면 됩니다.
> - **커스텀 VPC:** 터만 있는 **전원주택** — 대문(IGW)을 직접 달고 길(Route Table)을 직접 깔아야만 밖으로 나갈 수 있습니다.

| 항목 | 기본 VPC (Default) | 커스텀 VPC (Custom) |
|---|---|---|
| **생성** | AWS 계정 생성 시 자동 | 사용자가 직접 생성 |
| **서브넷** | 각 AZ마다 1개씩 자동 생성 | 직접 생성해야 함 |
| **인터넷 연결** | 기본 퍼블릭 서브넷 (IGW 연결됨) | 기본 프라이빗 상태 (IGW 없음) |
| **주의사항** | 삭제 시 서비스 제약 발생 가능 | IGW + 라우팅 직접 설정 필수 |

## 심화 연결 서비스

VPC 내부를 넘어 외부 환경과 연결되는 고급 리소스들입니다.

### Amazon EFS

가용영역 A의 서브넷과 가용영역 B의 서브넷에 각각 흩어진 EC2들이 공통으로 파일을 저장하고 공유할 수 있도록, 각 서브넷에 **'Mount Target(마운트 타겟)'**을 뚫어 연결하는 **공유 파일 시스템**입니다.

### AWS Direct Connect / VPN Connection

일반 퍼블릭 인터넷(Public Internet) 망을 타지 않고, 클라이언트에서 VPC 내부(Subnet)로 **안전하게 다이렉트로 꽂히는** 보안 연결 전용선 및 VPN 터널링 리소스입니다.
