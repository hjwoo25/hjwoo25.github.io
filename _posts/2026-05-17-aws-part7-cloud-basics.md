## 클라우드 컴퓨팅이란?

> **정의:** IT 리소스(서버, 저장소, 네트워크 등)를 인터넷을 통해 필요할 때 바로 쓸 수 있게 제공하는 것.

두 가지 핵심 개념만 기억하면 됩니다.

- **온디맨드(On-Demand):** 공급자가 일방적으로 주는 게 아니라, 사용자가 원할 때 즉시 제공하는 방식
- **쓴 만큼만 지불:** 서버를 빌려도 실제로 사용한 시간·용량만큼만 비용을 냄

> **중학생 비유:** 전기처럼 생각하면 됩니다.  
> 옛날에는 공장마다 발전기를 직접 돌렸지만, 지금은 한국전력에서 전기를 끌어다 쓰고 사용한 만큼만 전기요금을 냅니다.  
> 클라우드도 똑같이 — AWS라는 거대한 "컴퓨터 발전소"에서 필요한 만큼 빌려 쓰는 것입니다.

## 온프레미스 vs 클라우드: 집 짓기 vs 호텔 비유

> **집 짓기 = 데이터 센터 직접 운영 (온프레미스)**  
> **호텔 빌리기 = 클라우드 사용**

### 온프레미스 (직접 데이터센터 운영)

데이터센터는 서버를 호스팅하는 실제 건물입니다.  
서버 하드웨어, 네트워크 장비, 전기 시스템, 백업 발전기, 에어컨, 운영 인력까지 모두 직접 구축하고 관리해야 합니다.

| 구분 | 내용 |
|---|---|
| **장점** | 100% 내 마음대로 커스터마이징 가능, 데이터 주권이 완전히 내게 있음 |
| **단점** | 막대한 초기 투자 비용, 구축 기간이 오래 걸림, 직접 유지보수, 수요가 변해도 장비를 계속 안고 가야 함 |

### 클라우드 (AWS 등)

| 구분 | 내용 |
|---|---|
| **장점** | 초기 투자 비용 없음, 필요할 때 즉시 사용, 유지보수 불필요, 쓴 만큼만 지불 |
| **단점** | 인프라 소유권이 내게 없음 (내 집이 아닌 호텔), 인터넷 연결 필요 |

> **중학생 비유:**  
> - 온프레미스 = 내 집 짓기. 내 마음대로 리모델링 가능하지만, 집 살 돈·건축 비용·관리비 모두 내 부담.  
> - 클라우드 = 호텔 빌리기. 체크인하면 바로 쓸 수 있고, 청소도 호텔이 해주지만 내 집은 아님.

## 클라우드 컴퓨팅의 6가지 주요 장점

### 1. 자본 지출(CAPEX)을 운영 지출(OPEX)로 대체

> **비유:** 승용차를 구매(CAPEX)하는 대신 택시를 탈 때(OPEX)마다 요금 내는 것.

- **CAPEX:** 서버·장비를 미리 구매하는 거액의 초기 투자
- **OPEX:** 실제 사용한 만큼만 내는 운영 비용

처음부터 수억 원짜리 서버를 살 필요 없이, 쓴 만큼만 내면 됩니다.

### 2. 규모의 경제 혜택

> **비유:** 마트에서 낱개보다 박스째 사면 단가가 싼 것처럼 — AWS는 전 세계 수백만 고객을 위해 대량으로 서버를 운영하므로 단가가 극도로 낮아집니다.

AWS가 거대한 규모로 인프라를 운영하기 때문에, 고객이 혼자 서버를 사는 것보다 훨씬 저렴하게 이용할 수 있습니다.

### 3. 용량 추정 불필요

> **비유:** 뷔페 식당에서 음식이 딱 필요한 만큼만 나오는 것처럼.

기존 온프레미스는 "최악의 상황(피크 트래픽)"에 맞춰 미리 서버를 구매해야 해서, 평소에는 서버의 80%가 놀게 됩니다.  
클라우드는 트래픽에 맞춰 실시간으로 늘리고 줄일 수 있어 낭비가 없습니다.

### 4. 속도 및 민첩성 개선

> **비유:** 맥도날드 드라이브스루처럼 — 주문하면 즉시 나옵니다.

서버가 필요하면 AWS 콘솔에서 클릭 몇 번으로 **몇 분 안에** 생성 가능합니다.  
과거 온프레미스라면 서버 주문 → 배송 → 설치 → 설정까지 몇 주~몇 달이 걸렸습니다.

### 5. 비즈니스 자원 집중

> **비유:** 식당 사장님이 주방 청소·설거지 걱정 없이 요리에만 집중할 수 있는 것처럼.

서버실 관리, 장비 교체, 인프라 유지보수에 사람과 돈을 쓰는 대신, **핵심 서비스 개발**에만 집중할 수 있습니다.

### 6. 빠른 글로벌 확장

> **비유:** 게임 앱을 만들었는데, 클릭 몇 번으로 미국·일본·유럽 서버를 동시에 켤 수 있는 것처럼.

전 세계 수십 개 리전(데이터센터 지역)에 버튼 하나로 서비스를 배포할 수 있습니다.

## 클라우드 서비스 모델 (제공 수준에 따른 분류)

앱은 기본적으로 **네트워크 → 스토리지 → 컴퓨팅 → OS → 앱** 계층으로 구성됩니다.  
클라우드 제공자가 이 중 **어디까지 책임지느냐**에 따라 3가지로 나뉩니다.

> **라면 끓이기 비유로 한 번에 이해하기:**

| 모델 | 제공 범위 | 라면 비유 | 사용자가 할 일 |
|---|---|---|---|
| **IaaS** | 인프라(서버·네트워크·스토리지)만 제공 | 주방(가스레인지)만 빌려줌 | 냄비, 물, 라면까지 직접 가져와서 끓임 |
| **PaaS** | 인프라 + OS + 실행 환경 제공 | 주방 + 냄비 + 물까지 준비해줌 | 라면(코드)만 가져와서 넣으면 됨 |
| **SaaS** | 완성된 서비스 전체 제공 | 다 끓인 라면을 가져다 줌 | 그냥 먹기만 하면 됨 |

### IaaS (Infrastructure as a Service)

- 가상 컴퓨터(서버), 저장소, 네트워크 등 **인프라만 제공**
- 사용자가 OS 설치, 소프트웨어 설정, 앱 배포까지 직접 해야 함
- **대표 서비스:** Amazon EC2, Google Compute Engine
- **사용 대상:** 개발자, 시스템 엔지니어

### PaaS (Platform as a Service)

- 인프라 위에 **OS + 런타임 환경까지 제공**
- 코드만 올리면 실행됨 — 인프라·OS 관리 불필요
- **대표 서비스:** Firebase, Google App Engine, AWS Elastic Beanstalk
- **사용 대상:** 앱 개발자 (인프라 관리 없이 개발에만 집중)

### SaaS (Software as a Service)

- 완성된 **소프트웨어 서비스 자체**를 제공
- 설치나 개발 없이 그냥 사용만 하면 됨
- **대표 서비스:** Gmail, Slack, Dropbox, Google Docs, Zoom
- **사용 대상:** 일반 사용자

## 클라우드 배포 모델 (어디에 구축하느냐에 따른 분류)

### 공개형 (Public Cloud)

- 모든 서비스가 AWS 같은 클라우드 제공자의 인프라에서 실행
- 비용이 낮고 확장성이 높음
- **예:** AWS, Azure, Google Cloud

### 폐쇄형 (Private Cloud / 온프레미스)

- 기업 내부의 사설 데이터센터에서 직접 구축·운영
- 높은 커스터마이징과 강력한 보안 가능
- 초기 구축 비용과 유지보수 비용이 비쌈
- **예:** 은행, 군사 시스템

### 혼합형 (Hybrid Cloud)

- 폐쇄형 + 공개형을 함께 사용
- 메인 시스템은 내부(Private), 백업이나 추가 용량은 클라우드(Public)로 운영
- 온프레미스에서 클라우드로 넘어가는 **전환기**에 자주 사용

> **중학생 비유:**  
> - Public: 공공 도서관 (누구나 이용, 저렴, 내 전용 공간 없음)  
> - Private: 집에 개인 서재 구축 (완전 내 공간, 비쌈)  
> - Hybrid: 평소엔 집 서재 쓰다가 책이 너무 많아지면 공공 도서관도 함께 이용
