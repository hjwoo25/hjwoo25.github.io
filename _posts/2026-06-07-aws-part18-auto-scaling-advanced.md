Auto Scaling의 기본 동작(인스턴스 증감)을 넘어, **안정적인 운영과 세밀한 제어**를 위해 알아야 할 고급 기능들을 정리합니다.

---

## 1. 상태 확인 (Health Check) 및 유예 기간

Auto Scaling이 인스턴스의 생사를 판단하고 교체하는 기준입니다.

> **비유:** 항공사가 취항 기체의 상태를 점검하는 방식입니다.  
> 기체에 이상이 생기면(Unhealthy) 즉시 격납고로 돌리고 대기 중인 기체를 투입합니다.  
> 단, 방금 정비를 마친 신규 기체는 모든 시스템이 켜질 때까지 잠시 기다렸다가 점검을 시작합니다.

### 상태 확인 방식

| 방식 | 설명 |
|---|---|
| **EC2 상태 확인** | 하드웨어 수준의 정상 여부 확인 (기본값) |
| **ELB 상태 확인** | 실제 트래픽을 처리할 수 있는지 확인 (ELB 연동 시 권장) |

상태 확인에 실패하면(Unhealthy) Auto Scaling이 즉시 해당 인스턴스를 삭제하고 새 인스턴스로 교체합니다.

### Health Check Grace Period (유예 기간)

새로 생성된 인스턴스는 운영체제 부팅 → 애플리케이션 실행 → 트래픽 수신 준비까지 시간이 필요합니다.  
이 시간 동안 Health Check를 잠시 유예해 주는 준비 기간입니다.

```
기본값: 300초 (5분)

인스턴스 시작
  → [유예 기간 300초 동안 Health Check 보류]
  → 유예 기간 종료
  → Health Check 시작
  → 정상이면 InService / 비정상이면 즉시 교체
```

> 유예 기간이 너무 짧으면 아직 준비 중인 인스턴스를 Auto Scaling이 비정상으로 판단하여 불필요한 교체가 반복됩니다.

### 인스턴스 Warm Up

트래픽을 받기 전에 CloudWatch 지표 수집을 잠시 보류하여,  
**초기 부팅 시의 비정상적인 수치(CPU 급등 등)가 스케일링 판단에 반영되지 않도록** 하는 기능입니다.

```
신규 인스턴스 투입
  → Warm Up 기간 동안 CloudWatch 지표 제외
  → Warm Up 완료
  → 정상적으로 지표 수집 및 스케일링 판단에 포함
```

## 2. 인스턴스 축소 보호 (Instance Scale-In Protection)

트래픽이 줄어들어 Auto Scaling이 인스턴스를 삭제(Scale-In)하려 할 때, **특정 인스턴스만 삭제되지 않도록 보호**하는 기능입니다.

> **비유:** 비행 중인 기체는 착륙 전까지 격납고로 보낼 수 없습니다.  
> Auto Scaling이 감편을 결정해도, 이미 승객을 태우고 비행 중인 기체(중요 작업 실행 중인 인스턴스)는 착륙(작업 완료)할 때까지 건드리지 않습니다.

### 주요 사용 목적

```
✅ 대용량 비디오 인코딩 등 장시간 작업이 중간에 끊기지 않도록 보장
✅ 디버깅 목적으로 특정 인스턴스를 살려두고 로그 분석
✅ 배치 작업이 완료될 때까지 해당 인스턴스 유지
```

### 동작 방식

```
Scale-In 보호 활성화된 인스턴스
  → Auto Scaling이 삭제 대상으로 선정 시도
  → 보호 설정 감지 → 해당 인스턴스 건너뜀
  → 다른 인스턴스를 대신 종료

작업 완료 후
  → 보호 해제
  → 이후 Scale-In 발생 시 정상적으로 종료 대상이 됨
```

## 3. 관리 임시 해제 (StandBy)

작동 중인 특정 인스턴스를 **대기(StandBy) 상태로 전환**하여,  
Auto Scaling 관리와 ELB 트래픽 분산 대상에서 임시로 제외하는 기능입니다.

> **비유:** 기체를 잠시 대기선(터미널 옆 주기장)에 세워두는 것입니다.  
> 아직 격납고(Terminated)로 들어간 것은 아니지만, 승객도 안 태우고(ELB 트래픽 없음) 관제탑도 일단 신경 끈 상태입니다.  
> 정비가 끝나면 다시 활주로(InService)로 복귀시킵니다.

### InService vs StandBy 비교

| 상태 | ELB 트래픽 수신 | Health Check | 재사용 가능 |
|---|---|---|---|
| **InService** | ✅ | ✅ | — |
| **StandBy** | ❌ | ❌ (일시 중단) | ✅ (복귀 가능) |
| **Terminated** | ❌ | ❌ | ❌ |

### 주요 사용 목적

```
✅ 서비스에 영향 없이 특정 인스턴스 소프트웨어 직접 업데이트
✅ 장애 원인 디버깅 (트래픽 차단 후 로그 분석)
✅ 작업 완료 후 InService 상태로 즉시 복귀
```

## 4. 기능 일시 중지 및 재개 (Suspend / Resume Processes)

Auto Scaling이 백그라운드에서 자동 수행하는 프로세스들을 **개별적으로 켜거나 끌 수** 있습니다.

> **비유:** 항공사 자동 운항 관리 시스템의 특정 기능만 선택적으로 끄는 것입니다.  
> 전체 시스템을 중단하지 않고, "공항 간 기체 균형 조정 기능만 잠시 꺼라"처럼 세밀하게 제어합니다.

### 주요 제어 가능 프로세스

| 프로세스 | 설명 | 중지 시 효과 |
|---|---|---|
| `Launch` | 새 인스턴스 생성 | 더 이상 새 인스턴스를 추가하지 않음 |
| `Terminate` | 인스턴스 종료 | Scale-In이 발생해도 인스턴스를 삭제하지 않음 |
| `AZRebalance` | AZ 간 인스턴스 균형 조정 | 특정 AZ에 인스턴스가 몰려도 자동 재분배 안 함 |
| `Replace Unhealthy` | 비정상 인스턴스 교체 | 고장 난 인스턴스를 교체하지 않음 |
| `HealthCheck` | 상태 확인 수행 | Health Check 자체를 중단 |

```
사용 예시:
  배포 작업 중 → Launch, Terminate 일시 중지
  → 배포 완료 후 → Resume으로 재개
```

## 5. 수명 주기 후크 (Lifecycle Hooks)

인스턴스가 생성되는 중이거나 삭제되기 직전에 **일시 정지시키고 사용자 지정 로직을 실행**할 수 있게 해주는 기능입니다.

> **비유:** 기체의 취항 전·퇴역 전 절차입니다.  
> 취항 전(Pending): 모든 시스템 점검, 최신 항법 소프트웨어 설치 완료 후 승객을 태웁니다.  
> 퇴역 직전(Terminating): 기체 내부의 블랙박스 데이터를 안전하게 백업한 후 격납고로 들어갑니다.  
> 이 중간 단계 없이 바로 취항하거나 바로 퇴역시키면 중요한 절차가 누락됩니다.

### 동작 흐름

**인스턴스 시작 시 (Pending Hook):**

```
Auto Scaling이 인스턴스 생성 결정
  → 인스턴스 Pending:Wait 상태로 일시 정지
  → 사용자 로직 실행 (최신 소스코드 다운로드, 설정 파일 적용 등)
  → 완료 신호(complete-lifecycle-action) 전송
  → 인스턴스 InService 상태로 전환 → 트래픽 수신 시작
```

**인스턴스 종료 시 (Terminating Hook):**

```
Auto Scaling이 인스턴스 종료 결정
  → 인스턴스 Terminating:Wait 상태로 일시 정지
  → 사용자 로직 실행 (로그 파일 S3 백업, 연결 종료 처리 등)
  → 완료 신호 전송
  → 인스턴스 실제 종료
```

### 주요 사용 목적

| 시점 | 활용 사례 |
|---|---|
| **시작 전 (Pending)** | CI/CD 배포 (최신 소스코드 Pull), 설정 파일 주입, 외부 서비스 등록 |
| **종료 전 (Terminating)** | 로그 파일 S3 백업, 세션 데이터 저장, 외부 서비스에서 해제 |

> 기본 대기 시간은 **3600초(1시간)**이며, 그 안에 완료 신호를 보내지 않으면 자동으로 다음 단계로 넘어갑니다.
