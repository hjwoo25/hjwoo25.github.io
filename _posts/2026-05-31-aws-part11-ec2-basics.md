클라우드 하면 가장 먼저 떠오르는 서비스, **EC2**입니다.  
온프레미스 서버를 직접 사고 설치하고 유지보수하던 시대에서,  
버튼 몇 번으로 전 세계 어디서든 서버를 띄울 수 있는 시대로의 전환을 이끈 핵심 서비스입니다.

---

## Amazon EC2란?

> **정의:** 클라우드에서 안전하고 크기 조정이 가능한 컴퓨팅 파워를 제공하는 웹 서비스

> **한 줄 비유:** AWS라는 거대한 데이터센터에서 **필요한 만큼만 빌려 쓰는 가상 서버**입니다.  
> 마치 렌터카처럼, 필요할 때 빌리고 다 쓰면 반납합니다.

EC2는 **Elastic Compute Cloud**의 줄임말로, 'Elastic'이라는 단어처럼 필요에 따라 유연하게 크기를 늘리거나 줄일 수 있는 것이 핵심입니다.

---

## EC2의 4가지 주요 장점

### ① 초 단위 온디맨드 가격 모델

> **비유:** 택시처럼 탄 만큼만 냅니다.

- 서비스 요금을 **미리 약정하거나 선입금할 필요 없음**
- **초 단위**로 과금 → 1시간을 빌려도 실제 30분만 썼으면 30분치만 납부

```
기존 온프레미스:
서버 구매 → 설치 → 유지보수 → 몇 년치 비용 한번에 선납 💸

EC2:
인스턴스 시작 → 사용 → 중지 → 사용한 시간(초)만큼만 납부 ✅
```

---

### ② 빠른 구축과 확장성

> **비유:** 레고 블록처럼 필요할 때 바로 쌓고, 불필요하면 바로 뺄 수 있습니다.

- **단 몇 분** 만에 전 세계에 수백여 대의 인스턴스를 구축 가능
- 트래픽이 급증하면 인스턴스를 추가하고, 줄어들면 다시 축소

```
블랙프라이데이 이벤트 전날:
서버 10대 → 100대로 증설 (클릭 몇 번, 몇 분 내) ✅

이벤트 종료:
100대 → 다시 10대로 축소, 추가 비용 없음 ✅
```

---

### ③ 다양한 구성 방법 지원

| 사용 목적 | 적합한 인스턴스 |
|---|---|
| 일반 웹서버, 개발 환경 | 범용 (t, m 시리즈) |
| 머신러닝, GPU 가속 | 가속 컴퓨팅 (g, p 시리즈) |
| 게임 서버, 고성능 연산 | 컴퓨팅 최적화 (c 시리즈) |
| 대용량 데이터베이스 | 메모리 최적화 (r, x 시리즈) |

### ④ AWS 생태계 연동

| 연동 서비스 | 역할 |
|---|---|
| **Auto Scaling** | 트래픽에 따라 EC2 대수를 자동으로 조절 |
| **ELB (Elastic Load Balancer)** | 여러 EC2에 트래픽을 균등하게 분산 |
| **CloudWatch** | EC2의 CPU, 메모리, 네트워크 상태를 모니터링 |
| **IAM** | EC2에 역할을 부여해 다른 AWS 서비스 접근 권한 관리 |

## EC2가 해결하는 문제

| 문제 | 온프레미스 | EC2 |
|---|---|---|
| 초기 비용 | 서버 구매 비용 수천만원 | 없음 (사용 즉시 과금) |
| 구축 시간 | 수일~수주 | 수분 |
| 용량 조정 | 서버 추가 구매 필요 | 클릭 몇 번으로 즉시 확장 |
| 유지보수 | 직접 관리 (하드웨어 교체 등) | AWS가 물리 인프라 관리 |
| 글로벌 확장 | 해외 데이터센터 직접 구축 | 리전 선택만으로 해외 배포 가능 |

## 인스턴스란?

> **비유:** EC2가 아파트 단지라면, 인스턴스는 그 안의 **개별 세대(집)** 입니다.

| 구성 요소 | 역할 | 비유 |
|---|---|---|
| **인스턴스** | CPU + 메모리로 연산 처리 | 집에 사는 사람 (거주자) |
| **EBS** | 데이터 저장 (가상 하드드라이브) | 창고 (수납 공간) |
| **네트워크** | 인스턴스와 EBS를 연결 | 집과 창고를 잇는 통로 |

**중요한 제약:**  
인스턴스는 반드시 **하나의 가용영역(AZ) 안에** 존재해야 합니다.

---

## 인스턴스 명명 규칙

`c7gn.xlarge`를 예시로 각 파트를 분해해봅니다.

```
c   7   g n  .  xlarge
│   │   │ │     └── 인스턴스 크기
│   │   │ └──────── 추가 기능 (n: 네트워크 최적화)
│   │   └────────── 프로세서 종류 (g: Graviton)
│   └────────────── 세대 (숫자가 높을수록 최신)
└────────────────── 인스턴스 패밀리 (c: 컴퓨팅 최적화)
```

| 위치 | 의미 | 예시 |
|---|---|---|
| **패밀리** | 인스턴스의 목적/특성 | `c` (컴퓨팅), `r` (메모리), `g` (GPU) |
| **세대** | 숫자가 높을수록 최신 세대 | `7` → 7세대 |
| **프로세서** | 사용 CPU 종류 | `g` = Graviton(ARM), `a` = AMD, 없으면 Intel |
| **추가 기능** | 특화 기능 | `n` = 네트워크 최적화, `d` = 로컬 NVMe SSD 내장 |
| **크기** | 성능 규모 | nano < micro < small < medium < large < xlarge < 2xlarge ... |

> **💡 크기와 성능의 관계:**  
> 크기가 클수록 **CPU, 메모리, 네트워크 대역폭, EBS 통신 대역폭** 모두 비례해서 증가합니다.

## 인스턴스 패밀리 5가지

### ① 범용 (General Purpose) — `t, m, A1, Mac`

> **비유:** 만능 선수. 어느 포지션이든 무난하게 소화하는 올라운더입니다.

- CPU, 메모리, 네트워크 성능이 균형 잡혀 있음
- **일반 워크로드**에 적합

**주요 사용처:** 저렴한 웹서버, 소규모 DB, 개발/테스트 환경

---

### ② 컴퓨팅 최적화 (Compute Optimized) — `C`

> **비유:** 단거리 100m 달리기 선수. CPU 성능 하나만큼은 압도적입니다.

**주요 사용처:** 고성능 웹서버/API 서버, 게임 서버, 미디어 트랜스코딩

---

### ③ 메모리 최적화 (Memory Optimized) — `r, X, z`

> **비유:** 광대한 작업 책상을 가진 사람. 한꺼번에 엄청난 양의 데이터를 펼쳐놓고 작업합니다.

**주요 사용처:** 인메모리 DB (Redis, Memcached), 실시간 빅데이터 처리 (Apache Spark)

---

### ④ 가속 컴퓨팅 (Accelerated Computing) — `f, Inf, g, p`

> **비유:** CPU 대신 한 가지 일만 초고속으로 처리하는 전문 기계를 투입합니다.

| 타입 | 주요 용도 |
|---|---|
| `g` (GPU) | 머신러닝 학습, 3D 시각화 |
| `p` (GPU, 고성능) | 딥러닝 모델 학습, HPC |
| `Inf` (Inferentia) | AI 추론 최적화 |
| `f` (FPGA) | 게놈 분석, 금융 알고리즘 |

---

### ⑤ 저장 최적화 (Storage Optimized) — `h, i, d`

> **비유:** 초고속 물류창고. 데이터를 읽고 쓰는 속도 자체가 경쟁력입니다.

**주요 사용처:** 분산 파일시스템 (Hadoop), NoSQL DB (Cassandra, MongoDB)

---

## 패밀리 비교 요약

| 카테고리 | 타입 | 핵심 강점 | 대표 사용처 |
|---|---|---|---|
| 범용 | t, m, A1, Mac | 균형 잡힌 성능 | 웹서버, 개발환경 |
| 컴퓨팅 최적화 | C | CPU 집중 | 게임서버, 배치 처리 |
| 메모리 최적화 | r, X, z | 대용량 RAM | 인메모리 DB, Spark |
| 가속 컴퓨팅 | f, Inf, g, p | GPU/FPGA 가속 | 머신러닝, 3D |
| 저장 최적화 | h, i, d | 디스크 I/O | Hadoop, NoSQL |
